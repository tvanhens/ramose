# Launch checklist — flip these when the repo and the packages go public

The docs are written for the world the `release/npm-publishing` branch creates:
public repo, `@ramose/*` on npm, Apache-2.0. Until that lands, six places on the
site deliberately hedge. Each carries a marker so you can find them:

```sh
grep -rn "SWAP-ON-PUBLISH" website/src/content/docs
grep -rni "not on npm yet\|not published yet\|unpublished" website/src/content/docs
cd website && bun run check     # must stay at 0 errors after every edit
```

the second-class route.

## 2. When the GitHub repo becomes public

Nothing to edit — but everything starts working. Today `github.com/tvanhens/ripple`
404s for anonymous visitors, which breaks, silently and site-wide:

- the `git clone` line on the landing page and in Quickstart Path 1;
- the GitHub icon in the header and the "Edit page" link in every page footer;
- **21 "the code behind this figure" links** generated by `<Shot code=…>` — the
  mechanism the whole show-don't-tell strategy rests on;
- the `bench/RESULTS.md` citation behind every throughput number.

All 21 deep links were verified against the local repo: every file exists and
every `#La-Lb` range is real. They will work the moment the repo is public.

## 3. When the LICENSE lands on the default branch

`release/npm-publishing` adds Apache-2.0. The landing page's trust strip
(`index.mdx`, `.rg-trust`) deliberately names no license, because there is no
LICENSE file on `master` yet. Once there is, add it:
