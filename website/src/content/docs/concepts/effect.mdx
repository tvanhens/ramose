Ramose is built on [Effect](https://effect.website), a TypeScript library for describing work as values. You can use Ramose without learning it. Here is the 5% you will see, for someone who has built the first app.

## A Ramose call is a description, not a result

`db.query(query)` does not fetch rows. It returns an *Effect value*: a description of a read, with the result type and the possible errors in its type. Nothing happens until something runs it. The same is true of `db.transact(…)`, `db.pull(…)` and `db.install()`.

A **write** is one all-or-nothing group of changes ([glossary](/concepts/glossary/#write)). That is why a write can be built in one place and run in another, and why a failed step stops the whole thing before anything is sent.

## In React, the hooks run it for you

`useLive`, `useQuery` and `usePull` run reads and re-run them; `useTransact().run` runs a write from an event handler. You never see Effect:

```tsx title="examples/todos/src/App.tsx#todo-list"
const TodoList = () => {
  const { rows, error } = useLive(db, todoQuery);
  if (error !== undefined) return <p>offline…</p>;
  if (rows === undefined) return <p>loading…</p>;
  return (
    <ul>
      {rows.map((row) => (
        <TodoRowView key={row.id} row={row} />
      ))}
    </ul>
  );
};
```

```tsx title="examples/reef/src/app/screens/BoardScreen.tsx#use-transact"
  // Every write is one `run(...)`; a policy denial (or any DbError) becomes
  // a toast — enforcement is server-side, the UI is only a hint.
  const { run } = useTransact({
    onError: (error) => toast("error", errorMessage(error)),
  });
```

`run(effect)` returns a Promise; a policy denial arrives in `onError` as a readable message.

## Outside React: Effect.runPromise

Anywhere else — a script, a Worker, a test — `Effect.runPromise(effect)` runs one Effect and gives you a Promise. Reef opens a workspace this way:

```ts title="examples/reef/src/app/ramose.ts#open-workspace-provision"
    const connect = options?.connect ?? Ramose.connect;
    const ramose = connect({
      url: options?.url ?? RAMOSE_URL,
      token,
      fetch: options?.fetch,
      webSocket: options?.webSocket,
    });
    try {
      await provisionWorkspace(ramose.db(slug, Reef));
    } finally {
      await ramose.close();
    }
```

Every `db` method can be run this way directly; nothing else needs to be set up.

## Inside a write: yield*

A write's body is a generator. Read `yield*` as `await`: it runs the step and gives you its result. Reef's drag-and-drop is two steps:

```ts title="examples/reef/src/app/mutations.ts#move-issue"
export const moveIssue = (
  db: ReefDb,
  issueId: number,
  status: Status,
  rank: number,
) => db.run(moveIssueOp, issueId, { status, rank });
```

`function*` and `yield*` are plain JavaScript; Effect uses them so a write reads top to bottom. If any step fails, the write is not sent.

## Handling errors by name

On the app path, `await db.query(…)` / `db.run(…)` reject with the tagged class itself. Match with `try/catch` and `instanceof` / `_tag` — see [Errors](/reference/errors/).

The hatch (`db.effect.*`) still produces Effects. `runPromise` from `ramose/effect` (or `ramose/db/effect`) unwraps them so the Promise rejects with that same class, not a FiberFailure. Do not use `Effect.runPromise` on a Ramose Effect if you need `_tag` / `instanceof` to work.

Every failure a `db` call can produce is a named error: `TxRejected`, `Unauthorized`, `QueryBudgetExceeded`, `Unavailable`, `InvalidRequest`, `DatabaseNotFound`, `InternalError`, `NetworkError`, `OperationRejected`. A Worker that proxies those to HTTP uses `errorToHttp`:

```ts title="examples/kv-style/app.ts#error-to-http"
        // Tagged DbError → HTTP. One helper instead of a 9-arm catchTags.
        Effect.catch((e) => {
          const { status, body, headers } = Ramose.errorToHttp(Ramose.toDbError(e));
          return HttpServerResponse.json(body, { status, headers });
        }),
```

Hatch code (`db.effect.*`) can still `Effect.catchTags` by `_tag`. In React, `errorMessage(e)` from `ramose/react` turns any of them into a string. The full list, with status codes and what the user sees, is on [Errors](/reference/errors/).

## Words you can ignore for now

You may meet these in the reference pages; none is needed to build an app.

- **Layer** — wiring: how a program is given the things it needs.
- **Stream** — a stream of results over time; `db.live` returns one, `useLive` consumes it for you.
- **Fiber** — a running subscription; a live query is one.
- **Scope** — what closes a subscription when its owner goes away.

## When you want more

`import { layer, Databases } from "ramose/db/effect"` is the Effect-native twin of `Ramose.connect`; it provides a `Databases` service you `yield*` inside your own programs, and closes its connections when the program ends. A Worker talking to a deployed `Ramose.Server` uses `yield* Ramose.Databases(Server)` and `Ramose.layer` instead. Ramose tracks Effect 4, so the spellings are `Effect.catch`, `Effect.catchTags`, `effect/Schema` and `Context.Service`. The library's own guide is at [effect.website](https://effect.website).

App schemas do not import `effect/Schema` — they use `Ramose.string()`, `Ramose.Enum([...])`, and the other shorthands. A raw Effect Schema is the advanced form: `Ramose.Field(schema)` (or `import { Schema } from "ramose/effect"`), and operation input/output codecs stay Effect Schema.
