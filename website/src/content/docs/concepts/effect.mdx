The app path is TypeScript and `async`/`await`: `await db.query(…)`, `await db.run(…)`. React hooks run reads and wrap write promises. This page is the escape hatch for people who already use [Effect](https://effect.website), or who are wiring a Worker that does.

## Why a hatch exists

Ramose is built on Effect. The public `Db` unwraps that into promises and [subscriptions](/guides/live-queries/#outside-react). `db.effect` is the same handle returning Effect / Stream values, so a program that is already an Effect can `yield*` without a second wrapper.

Do not start here. [Getting started](/getting-started/quickstart/) and [Write data](/guides/transactions/) teach `db.run`.

## ramose/effect

`effect` is a dependency of `ramose`. Two copies in one tree produce mutually unassignable types. Declare it in your own `package.json` only at a version that agrees with Ramose's.

One subpath lets a resolver that refuses undeclared imports (pnpm without hoisting, Yarn PnP) avoid naming `effect` at all:

```ts
import { Schema, Effect, Layer, Stream, Redacted, pipe } from "ramose/effect";
```

It re-exports the module instances `effect` itself exports, so the two spellings are interchangeable.

App schemas do not import `effect/Schema` — they use `Ramose.string()`, `Ramose.Enum([...])`, and the other shorthands. A raw Effect Schema is the advanced field form: `Ramose.Field(schema)`. Operation input and output codecs stay Effect Schema.

## ramose/db/effect

`import { layer, Databases } from "ramose/db/effect"` is the Effect-native twin of `Ramose.connect`. It provides a `Databases` service you `yield*` inside your own programs, and closes its connections when the program ends. A Worker talking to a deployed `Ramose.Server` uses `yield* Ramose.Databases(Server)` and `Ramose.layer` instead:

```ts
const ramose = yield* Ramose.Databases(Server);   // provide Ramose.layer
const db = ramose.db("todos", Todos);
```

Reef's workspace provision is still `await db.run(…)` on the app path:

```ts title="examples/reef/src/app/ramose.ts#open-workspace-provision"
    const connect = options?.connect ?? Ramose.connect;
    const ramose = connect({
      url: options?.url ?? RAMOSE_URL,
      token,
      fetch: options?.fetch,
      webSocket: options?.webSocket,
    });
    try {
      await ramose.db(slug, Reef).run(provisionWorkspaceOp, {});
    } finally {
      await ramose.close();
    }
```

## db.effect

Every promise method has an Effect twin: `db.effect.query`, `db.effect.run`, `db.effect.install`, `db.effect.principal`, `db.effect.pull`, `db.effect.basis`. Live reads are Streams: `db.effect.live`, `db.effect.livePull`.

```ts
const report = yield* db.effect.run(addTodoOp, { title: "buy milk" });
const id = report.output.id;
```

There is no `db.effect.transact`. Writes are named operations on both surfaces.

## Errors

On the app path, `await db.query(…)` / `db.run(…)` reject with the tagged class itself. Match with `try/catch` and `instanceof` / `_tag` — see [Errors](/reference/errors/).

The hatch still produces Effects. `runPromise` from `ramose/effect` (or `ramose/db/effect`) unwraps them so the Promise rejects with that same class, not a FiberFailure. Do not use `Effect.runPromise` on a Ramose Effect if you need `_tag` / `instanceof` to work.

A Worker that proxies those to HTTP uses `errorToHttp`:

```ts title="examples/kv-style/app.ts#error-to-http"
        // Tagged DbError → HTTP. One helper instead of a 9-arm catchTags.
        Effect.catch((e) => {
          const { status, body, headers } = Ramose.errorToHttp(Ramose.toDbError(e));
          return HttpServerResponse.json(body, { status, headers });
        }),
```

Hatch code can still `Effect.catchTags` by `_tag`. Ramose tracks Effect 4, so the spellings are `Effect.catch`, `Effect.catchTags`, `effect/Schema` and `Context.Service`. The library's own guide is at [effect.website](https://effect.website).
