Ramose separates authority, persistence, and local interaction while keeping one public model. The architecture is optimized for many independent graph databases rather than one globally writable cluster.

## Request edge

One Cloudflare Worker terminates HTTPS, synchronization, and MCP. It verifies identity, resolves an authorized root or graph path, selects the deployed catalog server-side, applies request limits, and routes work to the graph's stateful components.

The Worker is stateless for correctness. MCP requests do not depend on sticky sessions or in-memory client state.

## One writer per graph

Each graph has one authoritative writer that orders operations, checks grants and visible targets, runs operation bodies, validates facts, assigns the next version, and commits all or nothing.

This is the source of simple uniqueness, exact operation receipts, dense ordering, and deterministic history. It is also the per-graph write ceiling. Independent child graphs have independent writers and progress in parallel.

## Immutable read values

Read copies serve immutable database values built from persisted indexes plus committed changes. A request selects current, as-of, or history semantics, filters that value for the principal, and only then evaluates the query.

Content-addressed index nodes and retained roots live in R2. Stateful coordination and recent change data live with the graph's Durable Objects. A failed storage write cannot expose a partial commit.

## Complete browser replicas

The browser receives logical authorized facts and opaque revisions, not physical indexes or raw transaction metadata. It persists one complete local value per active principal and graph, builds local indexes, and derives query results.

Snapshots install atomically. Resume streams authorized additions and removals. Incompatible catalog or read-view changes reset the committed replica while preserving compatible queued invocation identity.

## Graph routing

Configured deployment roots establish the first database and catalog binding. Every child binding is derived only after an authorized Graph row is resolved. Stable storage identity follows the parent and row identity; readable path names may change.

## Failure model

Clients retry transient transport and platform failures. Durable receipts make repeated operation delivery safe. Read copies and browser replicas can reset from a complete snapshot. Child cache eviction discards a whole inactive graph, never part of one.

The design avoids cross-graph transactions. A workflow spanning graphs is a sequence of independently committed operations with application-level compensation or reconciliation.
