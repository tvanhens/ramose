  <div class="rg-moment-copy">
    <h2 id="the-schema-is-typescript">The schema is TypeScript</h2>
    <p>Reef's whole data model is one file. Fields have types, references point at other records, and a list is just <code>cardinality: "many"</code>. Your app, your rules and your deploy import it — no codegen, no migration step.</p>
    <p class="rg-cta"><a href="/guides/catalog/">Define your data →</a></p>
  </div>
  <div class="rg-moment-code">

```ts title="examples/reef/src/domain/schema.ts:29-46 (annotated)"
export const Issue = Ramose.Namespace("issue", {
  title: Ramose.Attr(Schema.String),
  status: Ramose.Attr(Schema.String),
  priority: Ramose.Attr(Ramose.Long),
  // …
  assignee: Ramose.Attr(Ramose.Ref(() => User)),
  labels: Ramose.Attr(Ramose.Ref(() => Label), { cardinality: "many" }),
  privateNote: Ramose.Attr(Schema.String, {
    doc: "visible to the admin class only",
  }),
});
// issue.add(Issue.priority, "high") does not compile:
// priority is a number.
```

  </div>
</div>

    <h2 id="one-query-always-current">One query, always current</h2>
    <p>The board is one query, read with <code>useLive</code>. Drag a card in one window and every other window moves it too — no WebSocket code, no refetch anywhere in Reef.</p>
    <p>Ramose is built on <a href="https://effect.website">Effect</a>. In React you rarely see it — the hooks run it for you. <a href="/concepts/effect/">Effect in five minutes →</a></p>
    <p class="rg-cta"><a href="/guides/live-queries/">Live queries →</a></p>
  </div>
  <div class="rg-moment-code">
    <Shot src="/reef/live-sync.gif" alt="Two Reef windows stacked; a card dragged to Done in the top window moves in the bottom one too" caption="The live pill pulses on every update." code="examples/reef/src/app/screens/BoardScreen.tsx:234-238" />

```ts title="examples/reef/src/domain/queries.ts:70-77 · app/screens/BoardScreen.tsx"
export const boardQuery = Query.q(() =>
  pipe(
    Query.entities(Issue),
    Query.select(boardShape),
    Query.orderBy(Issue.rank, "asc"),
  ),
);
// …
const db = useDb(slug, Reef);
const board = useLive(db, boardQuery);
```

<div class="rg-moment">
  <div class="rg-moment-copy">
    <h2 id="permissions-are-part-of-the-database">Permissions are part of the database</h2>
    <p>One policy says who may read and write each field. The buttons are just polite — the server refuses the write.</p>
    <p>Because the policy and the shapes your screens read are both values, <code>Ramose.Policy.compile(policy, &#123; pulls &#125;)</code> checks them against each other at deploy time — tighten a rule a screen depends on and the deploy fails, rather than that screen quietly emptying for one customer.</p>
    <p>Ramose verifies sign-in tokens; it never issues them. Bring Better Auth (Reef does), Clerk, Auth0, WorkOS — any provider that publishes signing keys.</p>
    <p class="rg-cta"><a href="/guides/permissions/">Permissions →</a></p>
  </div>
  <div class="rg-moment-code">

```ts title="examples/reef/src/domain/policy.ts:50-61 (comment simplified)"
issue: {
  read: true,
  create: P.class("member"),
  add: { class: "member", rule: ownIssue },
  retract: { class: "member", rule: ownIssue },
  retractEntity: { class: "member", rule: ownIssue },
  preset: [P.preset(Issue.creator, P.principal)],
  attrs: [
    // Only admins receive this field; the server strips it for others.
    P.attr(Issue.privateNote, { read: P.class("admin") }),
  ],
},
```

<h2 id="instead-of-what" class="rg-h2">Instead of what?</h2>
<p class="rg-lede">The honest trade against what you'd use otherwise:</p>

<div class="rg-vs">
<table>
  <thead>
    <tr><th>Instead of</th><th>Same idea</th><th>What's different, and what you give up</th></tr>
  </thead>
  <tbody>
    <tr><th>Convex</th><td>queries that re-run themselves</td><td>runs in <em>your</em> Cloudflare account; a database per customer is a function call. No hosted dashboard, scheduled functions or file storage.</td></tr>
    <tr><th>Supabase</th><td>rules enforced by the database</td><td>rules per field, deny by default, checked against your screens at deploy. No SQL; bring your own sign-in and file storage.</td></tr>
    <tr><th>Instant / Firebase</th><td>read and write from the browser, it stays live, per-user rules</td><td>typed schema in TypeScript; one deploy you own. No console, no managed infra, no offline SDK.</td></tr>
    <tr><th>D1 + Drizzle, or a Durable Object + SQLite</th><td>the same Cloudflare primitives, your account</td><td>already assembled: live fan-out, per-customer routing, permissions, history. You give up SQL.</td></tr>
    <tr><th>Postgres + an ORM</th><td>typed access</td><td>no migration rewrites old data; live queries and history come standard. No SQL, no planner, no cross-database joins.</td></tr>
  </tbody>
</table>

<h2 id="how-it-works" class="rg-h2">How it works</h2>
<p class="rg-lede">Three parts, one deploy.</p>

<div class="rg-how">
  <div class="rg-how-box">
    <span class="rg-step">writes</span>
    <h3>One writer per database</h3>
    <p>Writes commit in order; no conflicts, no "eventually".</p>
  </div>
  <div class="rg-how-box">
    <span class="rg-step">storage</span>
    <h3>Storage keeps every version</h3>
    <p>A write is durable before your call returns; nothing is rewritten, so yesterday is still readable.</p>
  </div>
  <div class="rg-how-box">
    <span class="rg-step">reads</span>
    <h3>Reads run next to your users</h3>
    <p>On copies, so a slow read never blocks a write.</p>
  </div>
</div>
