Ramose is a database for TypeScript applications that need to work locally, synchronize in realtime, and expose the same product safely to AI agents.

You define three things in code:

- a **schema** describing entities, traits, fields, relations, and graph boundaries;
- a **policy** deciding which facts and operations each principal may use;
- **operations** containing every authoritative change the product can make.

From that model, your web app gets typed local queries, durable offline mutations, and synchronization. Your deployment also gets one MCP endpoint with three stable tools: `describe`, `query`, and `mutate`.

<SurfaceMap />

## The unusual part

A Ramose deployment is a **graph of graphs**. One database can contain ordinary rows that open child databases. An organization can be a graph containing projects; a project can be a graph containing tasks. Each graph has its own schema, policy, write stream, offline cache boundary, and throughput ceiling.

That gives you an explicit place to put isolation and scale. It also means graph boundaries are an important modeling decision, not just deployment configuration.

## What the application feels like

```tsx
const tasks = useQuery(
  projectDb.query.from(Task).where({ done: false }).orderBy(Task.createdAt),
)

task.mutate.setDone({ done: true })
```

Queries run against a complete authorized local database. A cached answer can render before the network is available. Mutations are queued durably, may project an immediate local result, and are committed by the server through the operation you declared.

## Where Ramose fits

Choose Ramose when you want:

- an offline-first or realtime product without building a cache and sync protocol;
- strong tenant or domain isolation through nested graph boundaries;
- application and agent access governed by the same rules;
- typed history, relations, and operations without running a managed database service;
- deployment into your own Cloudflare account.

Do not choose it for ad-hoc SQL analytics, cross-graph joins, full-text search, or a workload that must atomically update several graphs. Ramose is pre-release and intentionally optimizes for fresh applications over compatibility with earlier APIs.
