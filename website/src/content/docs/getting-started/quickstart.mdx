This guide builds the authoring and deployment half of a todo database. The
current package intentionally does not include an online application client;
schemas, queries, pulls, and operations are portable declarations consumed by
the authoritative peer and future data-plane adapters.

## Install

```sh
mkdir ramose-todos
cd ramose-todos
bun init -y
bun add ramose effect@rc
```

Effect is a required peer because operation input and output codecs are Effect
Schemas. Alchemy is installed by Ramose and supplies the deployment CLI.

## Define the schema

Create `schema.ts`:

```ts
import * as Ramose from "ramose/db";

export const Todo = Ramose.Entity("todo", {
  title: Ramose.string(),
  done: Ramose.boolean(),
  createdAt: Ramose.timestamp(),
});

export const Todos = Ramose.Schema({ todo: Todo });
```

Entity and field names become stable catalog identities. Changing a name later
is a migration, not a display-label edit.

## Author a query

Create `todos.ts`:

```ts
import * as Ramose from "ramose/db";
import * as S from "effect/Schema";
import { Todo } from "./schema.ts";

export const openTodos = Ramose.Query.from(Todo)
  .where({ done: false })
  .select({
    id: Todo.id,
    title: Todo.title,
    createdAt: Todo.createdAt,
  })
  .orderBy(Todo.createdAt, "desc");
```

The query is a typed immutable value. Constructing it performs no network
request.

## Author an operation

In the same file, declare an authoritative write:

```ts
export const addTodo = Ramose.Operation(
  "todo/add",
  {
    input: S.Struct({ title: S.String }),
    output: S.Struct({ id: Ramose.EntityId }),
    doc: "Add a todo",
  },
  (op, input) => ({
    id: op.put(Todo, {
      title: input.title,
      done: false,
      createdAt: new Date(),
    }),
  }),
);

export const operations = Ramose.defineOperations(Todos, {
  addTodo,
  setDone: Ramose.Operation.patch("todo/set-done", Todo, ["done"]),
});
```

The body builds transaction data for authoritative execution. It is not an
optimistic client callback, and `ramose/db` does not run it against local
state.

## Deploy the peer

Create `alchemy.run.ts`:

```ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as Ramose from "ramose";
import { Todos } from "./schema.ts";
import { operations } from "./todos.ts";

const server = Ramose.Server("Ramose", {
  databases: { todos: Todos },
  operations,
});

export default Alchemy.Stack(
  "ramose-todos",
  {
    providers: Layer.mergeAll(Cloudflare.providers(), Ramose.providers()),
    state: Cloudflare.state(),
  },
  Effect.gen(function* () {
    yield* server;
  }),
);
```

`ramose/worker` is resolved internally by the resource. If you configure a
Cloudflare Worker directly, pass `import.meta.resolve("ramose/worker")` where
the tool expects a filesystem path.

Run the stack with:

```sh
bun alchemy deploy alchemy.run.ts
```

The deployed server exposes health and authoritative database routes. External
`/db/*` access remains fail-closed during the authorization redesign; this
guide stops at the supported authoring and deploy boundary.
