In two minutes you will have a todo app running on your machine: a typed
schema, a database behind it, and a list that updates itself when you write.
The local half needs no account and no external database — everything runs on
your laptop.

You need [Bun](https://bun.sh) — verified on 1.3.10. Nothing else: no Docker,
no Postgres, no Cloudflare account.

:::note[Pre-release]
Ripple is not on npm. Every package in the repository is private and points at
TypeScript source, so today you run it from a clone. That is what step 1 does.
:::

## Run the app

<Steps>

1. **Get the repository.**

   ```sh title="Terminal"
   git clone https://github.com/tvanhens/ripple
   cd ripple
   bun install
   ```

   Every command below runs from that directory. You should see `bun install`
   finish with a `node_modules/` at the repository root; the examples resolve
   their imports through it, which is why they are always run from the root.

2. **Start it.** Leave this terminal running.

   ```sh title="Terminal"
   bun run dev:todos
   ```

   Alchemy brings up the peer — the Worker that serves your databases — on
   **:1337**, then starts Vite on **:5173** and hands it `VITE_RIPPLE_URL`, so
   you never set it yourself. You will see:

   ```
   [Peer] ready at http://localhost:1337
   [Ui] ready at http://localhost:5173/
   Done: 10 succeeded
   ```

   The UI is pinned with `--strictPort`, so a busy :5173 fails loudly instead
   of quietly moving to :5174.

   <details>
   <summary>What that script expands to</summary>

   ```sh
   CI=1 ALCHEMY_STATE=local \
     CLOUDFLARE_ACCOUNT_ID=0123456789abcdef0123456789abcdef \
     CLOUDFLARE_API_TOKEN=x \
     bun alchemy dev examples/todos/alchemy.run.ts
   ```

   The account id is a placeholder and the API token is the literal letter
   `x`: `ALCHEMY_STATE=local` keeps the whole stack in miniflare on your
   machine, so nothing is sent to Cloudflare and nothing is billed. The script
   defaults each variable only when it is unset, so run this form if you want
   to override one.

   </details>

   :::note[A harmless-looking scare]
   When a tab closes you may see workerd print `The Workers runtime canceled
   this request because it detected that your Worker's code had hung`. That is
   the local emulator reaping a live-query socket, not a crash — the peer keeps
   serving.
   :::

3. **Check it.** From a second terminal:

   ```sh title="Terminal — checkpoint"
   curl http://localhost:1337/health
   # {"ok":true,"service":"ripple","stage":"dev","time":1755500000000}
   ```

   Optional, and four seconds: `bun test examples/todos` — four passing tests
   against a real connection, driving the same `todoQuery` and `addTodo` this
   page documents below.

4. **Open the app.** Vite is already serving `http://localhost:5173/`. You
   should see a heading, a text box, and a list — empty on a first run.
   Alchemy keeps its local state in the repository between runs, so anything
   you added earlier is still there. Type "buy milk", press add, and the row
   appears.

5. **Watch a write travel.** In the browser, tick a todo's checkbox. The list
   re-renders without a refetch: nothing in the app calls "reload" after a
   write.

   That is a live query. `db.live(todoQuery)` is a stream of rows; a write
   advances the connection's position in the database, and every standing query
   on that connection re-runs against the new position.

   :::note[Two tabs, locally]
   On the local emulator writes do not propagate between isolates, so a second
   tab picks them up on reload. Your own tab always updates, because its own write
   moves its own connection forward. Against a deployed peer, every connected
   client updates.
   :::

6. **Deploy it (optional).** The same file that ran under miniflare provisions
   the real thing:

   ```sh title="Terminal"
   bun alchemy deploy examples/todos/alchemy.run.ts
   ```

   This one needs real credentials — a `CLOUDFLARE_API_TOKEN` and your
   `CLOUDFLARE_ACCOUNT_ID`. See [Deploy with
   Alchemy](/guides/deploy/) for stages and teardown, and read [Before
   production](/guides/before-production/) first: a freshly deployed peer
   accepts requests from anyone until you configure a policy.

</Steps>

Ctrl-C in the terminal running `bun run dev:todos` stops the peer and the UI
together.

## What you just ran

Four files, and you can copy all of them.

**The catalog** is the schema, shared by the deploy script, the browser, and
any Worker that talks to this database:

```ts title="examples/todos/schema.ts"
import * as Ripple from "@ripple/alchemy/db";
import * as Schema from "effect/Schema";

export const Todo = Ripple.Namespace("todo", {
  title: Ripple.Attr(Schema.String),
  done: Ripple.Attr(Schema.Boolean),
  createdAt: Ripple.Attr(Ripple.Instant),
});

export const Todos = Ripple.Catalog({ todo: Todo });
```

**The deploy script** declares the Worker that serves the database and installs
that catalog on the name `todos`. Naming a database is all there is to creating
one — there is no provisioning step:

```ts title="examples/todos/alchemy.run.ts"
export const TodosDb = Ripple.Database("todos", {
  server: Server,
  catalog: Todos,
});
```

Ripple is built on [Effect](https://effect.website). Its API returns Effect
values — descriptions of work — so `Effect.runPromise(…)` executes one of
those values from the browser (nothing a `Db` returns needs an environment),
and `yield*` inside `db.transact` sequences the steps of a write. That is all
the Effect the rest of this path needs.

**The client** is one `Ripple.connect` handle for the page: a plain object, no
runtime to build, nothing to dispose but `ripple.close()`. Copy this file as it
stands — the token guard matters, because your local peer has no token and
wrapping an undefined one crashes on the first request:

```ts title="examples/todos/src/db.ts"
import * as Ripple from "@ripple/alchemy/db";
import * as Effect from "effect/Effect";
import * as Redacted from "effect/Redacted";
import { Todos } from "../schema.ts";

const token = import.meta.env.VITE_RIPPLE_TOKEN;

const ripple = Ripple.connect({
  url: import.meta.env.VITE_RIPPLE_URL ?? "http://localhost:8787",
  token:
    token === undefined || token === ""
      ? undefined
      : Effect.succeed(Redacted.make(token)),
});

export const db = ripple.db("todos", Todos);
```

**The queries and writes** live in one module so the app and its tests drive
exactly the same code:

```ts title="examples/todos/src/todos.ts"
import * as Ripple from "@ripple/alchemy/db";
import type { Db } from "@ripple/alchemy/db";
import { Todo, type Todos } from "../schema.ts";

export type TodosDb = Db<typeof Todos>;

/** The row shape, named once so a query and a `pull` can share it. */
export const todoShape = {
  id: Todo.id,
  title: Todo.title,
  done: Todo.done,
  createdAt: Todo.createdAt,
} as const;

/** A standing query is a value: run it once, run it live, or run it in the past. */
export const todoQuery = Ripple.query(Todo)
  .orderBy(Todo.createdAt, "asc")
  .select(todoShape);

/** One row from that query — inferred from it, never restated by hand. */
export type TodoRow = Ripple.Row<typeof todoQuery>;

export const addTodo = (db: TodosDb, title: string) =>
  db.transact(function* (tx) {
    const t = yield* tx.entity();
    yield* t.add(Todo.title, title);
    yield* t.add(Todo.done, false);
    yield* t.add(Todo.createdAt, new Date());
  });
```

The shipped file also exports `pullTodo`, `setDone`, and `deleteTodo`, cut here
for length; the code above is as shipped, comments aside.

`db.live(todoQuery)` in `src/App.tsx` is what redrew the list, and the
`useLive` hook in `src/useLive.ts` — about a dozen lines — is all it takes to
turn that stream into React state.

## Next

Your local peer is **open**: it has no policy, so every caller is an
administrator. That is right for a laptop and wrong for the internet.

- [Permissions in 10 minutes](/guides/permissions/) — one rule, one denied
  write, and what the client sees when it is denied.
- [Query and pull](/guides/queries/) — filters, refs, and the shape of a
  result.
- [Live queries](/guides/live-queries/) — what re-runs, when, and what it
  costs.

The examples in the repository are small enough to read in one sitting:

- [`examples/reef`](https://github.com/tvanhens/ripple/tree/master/examples/reef)
  — a Linear-style, multi-tenant issue tracker where every workspace is its own
  database, with Better Auth JWTs and a compiled policy. `bun run dev:reef`
  (peer on :1337, app on :5173).
- [`examples/todos`](https://github.com/tvanhens/ripple/tree/master/examples/todos)
  — the app you just ran: a catalog, a live query, and typed writes in under two
  hundred lines of React.
- [`examples/kv-style`](https://github.com/tvanhens/ripple/tree/master/examples/kv-style)
  — one Worker serving a database per customer, with every client error mapped
  to a status code.
