Get a Ramose app running on your laptop in under ten minutes. Path 1 runs Reef, the example issue tracker — the fastest way to see live sync, roles and time travel. Path 2 starts your own app from the todo template.

<Learn learn={["Run a realtime, multi-tenant app locally", "See a live query, a refused write and time travel", "Start your own app from a template"]} minutes={10} />

You need git and [Bun](https://bun.sh) 1.x (`curl -fsSL https://bun.sh/install | bash`). No Cloudflare account, no Docker. Path 1 starts from a clone, because Reef lives in this repository. Path 2 installs `@ramose/*` from npm. Ramose is pre-release, so expect the API to move between versions.

## Path 1: run Reef

<Steps>

1. ### Get the code

   ```sh frame="terminal"
   git clone https://github.com/tvanhens/ramose && cd ramose && bun install
   ```

2. ### Start it

   ```sh frame="terminal"
   bun run dev:reef
   ```

   Wait for `Done: 8 succeeded` and three URLs: `:1337` the Ramose server, `:1338` the sign-in Worker, `:5173` the app. The **Ramose server** is the one Cloudflare Worker that serves all your databases; Ramose's code calls it the peer ([glossary](/concepts/glossary/#server)).

   Alchemy is the TypeScript deploy tool Ramose uses: one file declares your Workers and storage; `bun alchemy dev` runs it on your laptop, `bun alchemy deploy` ships it to Cloudflare.

   <details>
   <summary>If Alchemy asks you to log in</summary>

   The local Cloudflare emulator wants placeholder credentials, and an interactive login fails in CI-like shells. `bun run dev:reef` already sets them; you only need the prefix if you run `bun alchemy dev` directly:

   ```sh frame="terminal"
   CI=1 ALCHEMY_STATE=local \
     CLOUDFLARE_ACCOUNT_ID=0123456789abcdef0123456789abcdef \
     CLOUDFLARE_API_TOKEN=x \
     bun alchemy dev examples/reef/alchemy.run.ts
   ```

   The account id is a placeholder and the token is the literal letter `x`. `ALCHEMY_STATE=local` keeps the whole stack on your machine, so nothing is billed. Each variable is only defaulted when unset.

   </details>

   :::note[A harmless-looking scare]
   `your Worker's code had hung` lines are the local emulator closing a socket, not a crash. [Why that line appears](/guides/troubleshooting/#the-terminal-says-the-workers-code-had-hung).
   :::

3. ### Sign up and create a workspace

   Open [http://localhost:5173](http://localhost:5173) and **Create account** (verified on the spot, no email). Then **New workspace**, type a name — the pictures here use `Tidepool` — and **Create**. A workspace is one customer's isolated data — its own database ([glossary](/concepts/glossary/#workspace)).

   <Shot src="/reef/workspace-create.png" alt="Reef's New workspace form with the name Tidepool typed in, and a preview line beneath it reading ramose.db(&quot;tidepool&quot;).install()" caption="Create runs ramose.db(&quot;tidepool&quot;).install() from the browser — the workspace is its own database." code="examples/reef/src/app/mutations.ts:28-45" />

   The pictures here come from a demo account with two workspaces and fifteen issues; yours will look sparser.

4. ### Put issues on the board

   Click **Add sample issues**. Drag one to **Done**.

   <Shot src="/reef/board-dark.png" alt="Reef's board in dark theme: four columns — Backlog, Todo, In Progress, Done — of issue cards with coloured labels, priorities and assignee avatars" caption="The sample issues arrived in one write; the board is one live query." code="examples/reef/src/domain/queries.ts:66-68" />

5. ### Open a second window

   Same URL, same account. Drag a card in one; watch it move in the other. The `live` pill pulses on every update.

   <Shot src="/reef/live-sync.gif" alt="Two Reef windows stacked; a card dragged in the top one moves in the bottom one" caption="One live query drives both windows; the live pill pulses on each update." code="examples/reef/src/app/screens/BoardScreen.tsx:264-267" />

   That is a live query — a query that re-runs itself when the database changes ([glossary](/concepts/glossary/#live-query)). `useLive(db, boardQuery)` re-ran; there is no refetch code in Reef.

6. ### Travel in time

   Click **Time travel**, drag the slider left, then **Back to live**. That is **time travel**: reading the database as it was at an earlier version ([glossary](/concepts/glossary/#time-travel)).

   <Shot src="/reef/time-travel.png" alt="Reef's board under a blue time-travel bar reading db.asOf(27) of 42, the header pill reading paused, showing fewer cards than live" caption="The same query, read as the database was at an earlier version number." code="examples/reef/src/app/screens/BoardScreen.tsx:448-460" />

7. ### See a rule refuse a write

   *(optional, 2 min)* **Invite** `viewer@example.com` as **viewer**. In a private window, sign up with that email, accept the invitation and open the board. Drag a card: a red toast says `retract denied on :issue/status` and the card snaps back. Buttons are hidden for viewers on purpose; the drag is the proof that a **role** ([glossary](/concepts/glossary/#role)) is enforced by the server, not the UI.

   <Shot src="/reef/denied-toast.png" alt="A viewer's Reef board with a red toast reading retract denied on :issue/status and a VIEWER badge in the header" caption="The server refused the write; the UI only reported it." code="examples/reef/src/app/screens/BoardScreen.tsx:241-245" />

8. ### What you just ran

   Three files are the whole data layer: `schema.ts` — what exists · `queries.ts` — what screens read · `policy.ts` — who may. The heart of the schema (Ramose calls it a *catalog* — [glossary](/concepts/glossary/#schema)):

   ```ts title="examples/reef/src/domain/schema.ts:29-46"
   export const Issue = Ramose.Namespace("issue", {
     title: Ramose.Attr(Schema.String),
     /** One of {@link STATUSES}. */
     status: Ramose.Attr(Schema.String),
     /** 0 none · 1 low · 2 medium · 3 high · 4 urgent. */
     priority: Ramose.Attr(Ramose.Long),
     creator: Ramose.Attr(Ramose.Ref(() => User)),
     assignee: Ramose.Attr(Ramose.Ref(() => User)),
     labels: Ramose.Attr(Ramose.Ref(() => Label), { cardinality: "many" }),
     // …
   });
   ```

   Try it: in `src/app/mutations.ts:100` change `draft.priority` to `"high"` — your editor underlines it; priority is a number. [Tour of Reef](/getting-started/tour-of-reef/) maps every screen to its code.

9. ### Stop

   Ctrl-C in the terminal.

</Steps>

## Path 2: start your own app

The smallest Ramose app is a todo list: a schema, a deploy file, one query, one component. Get it running here; [Build your first app](/getting-started/first-app/) walks through every line.

<Tabs syncKey="install">
<TabItem label="npm">

```sh frame="terminal"
npm create vite@latest my-app -- --template react-ts && cd my-app
npm install @ramose/alchemy @ramose/worker @ramose/react alchemy effect
```

`bun add` and `pnpm add` work the same. Copy the files from [`examples/todos`](https://github.com/tvanhens/ramose/tree/master/examples/todos) and change the Vite template's `src/main.tsx` to `import { App } from "./App.tsx";`. Then start everything — Alchemy runs the whole stack on your laptop (see *If Alchemy asks you to log in* above):

```sh frame="terminal"
bun alchemy dev alchemy.run.ts
```

</TabItem>
<TabItem label="Inside the clone">

The same code, resolved from source rather than npm — which is what you want if you are also changing Ramose itself. Skip the first line if you already ran Path 1.

```sh frame="terminal"
git clone https://github.com/tvanhens/ramose && cd ramose && bun install
bun run dev:todos
```

</TabItem>
</Tabs>

Open [http://localhost:5173](http://localhost:5173), add "buy milk", then open a second tab — it is already there. Two windows on the same database update each other within about a second, locally and deployed.

### What you just started

Six files, about 240 lines. The **schema** ([glossary](/concepts/glossary/#schema)) is the one to read first:

```ts title="examples/todos/schema.ts:1-10"
import * as Ramose from "@ramose/alchemy/db";
import * as Schema from "effect/Schema";

export const Todo = Ramose.Namespace("todo", {
  title: Ramose.Attr(Schema.String),
  done: Ramose.Attr(Schema.Boolean),
  createdAt: Ramose.Attr(Ramose.Instant),
});

export const Todos = Ramose.Catalog({ todo: Todo });
```

The deploy file names the three things the Ramose server needs on Cloudflare — a storage bucket where every version is kept, and two Durable Objects (Cloudflare's single-instance stateful Workers): the writer and the read copy. You name them; you never write them. [Why these three things →](/concepts/architecture/#what-runs-where)

<details>
<summary>The deploy file — copy it, don't study it yet</summary>

```ts title="resources.ts"
import * as Ramose from "@ramose/alchemy";
import * as Cloudflare from "alchemy/Cloudflare";

const Store = Cloudflare.R2.Bucket("Store");
const Transactor = Cloudflare.DurableObject("TransactorDO", { className: "TransactorDO" });
const Replica = Cloudflare.DurableObject("QueryReplicaDO", { className: "QueryReplicaDO" });

export const RamoseWorker = Cloudflare.Worker("Peer", {
  // The published package. Inside a clone of this repository it is a path
  // instead: "./packages/worker/src/index.ts".
  main: "@ramose/worker",
  compatibility: { date: "2025-06-01", flags: ["nodejs_compat"] },
  env: { STORE: Store, TRANSACTOR: Transactor, REPLICA: Replica },
});

export const Server = Ramose.Server("Ramose", { worker: RamoseWorker });
```

```ts title="alchemy.run.ts"
import * as Ramose from "@ramose/alchemy";
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Command from "alchemy/Command";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import { Server } from "./resources.ts";
import { Todos } from "./schema.ts";

export const TodosDb = Ramose.Database("todos", { server: Server, catalog: Todos });

export const Ui = Command.Dev(
  "Ui",
  Effect.gen(function* () {
    const server = yield* Server;
    return {
      command: "bunx vite . --port 5173 --strictPort",
      env: { VITE_RAMOSE_URL: server.url },
    };
  }),
);

export default Alchemy.Stack(
  "ripple-todos",
  {
    providers: Layer.mergeAll(
      Cloudflare.providers(),
      Ramose.providers(),
      Command.providers(),
    ),
    state: Alchemy.localState(),
  },
  Effect.gen(function* () {
    const server = yield* Server;
    yield* TodosDb;
    const ui = yield* Ui;
    return { peerUrl: server.url, uiUrl: ui.url };
  }),
);
```

</details>

The other four files are the app itself: `src/db.ts` connects to the server, `src/todos.ts` holds the query and the three writes, `src/App.tsx` renders the list, and `src/main.tsx` mounts it.

*Ramose is built on [Effect](https://effect.website). In React you rarely see it — the hooks run it for you; inside `db.transact` you write `yield*`. ([Effect in five minutes](/concepts/effect/))*
