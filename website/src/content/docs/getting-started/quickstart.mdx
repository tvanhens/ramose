You will add Ramose to a Vite React app: a typed schema, a database behind it,
and a list that updates itself when you write. The local half needs no
account and no external database — everything runs on your laptop.

You need [Node](https://nodejs.org) 20+ or [Bun](https://bun.sh). Nothing
else: no Docker, no Postgres, no Cloudflare account.

:::note[Pre-release]
Ramose is pre-release. The packages are on npm; the API may still move.
:::

## Add it to an app

<Steps>

1. **Scaffold and install.** Skip the scaffold if you already have a Vite
   React app.

   ```sh title="Terminal"
   npm create vite@latest todos -- --template react-ts
   cd todos
   npm install @ramose/alchemy @ramose/worker @ramose/react alchemy effect
   ```

   `bun add` and `pnpm add` work the same. Three Ramose packages, on purpose:

   | package | what it is |
   | --- | --- |
   | `@ramose/alchemy` | the catalog, the client (`@ramose/alchemy/db`), and the Alchemy resources |
   | `@ramose/worker` | the peer Worker — you name it as `main`, you do not copy it |
   | `@ramose/react` | `useLive` and `useTransact` |

   The packages ship compiled ESM with type declarations and source maps, so
   no bundler or `tsconfig` setting is required. TypeScript source ships
   alongside it and is what Bun resolves, which is why stack traces point at
   real source rather than compiled output.

2. **Write the catalog.** One file, shared by the stack, the browser, and any
   Worker that talks to this database:

   ```ts title="src/schema.ts"
   import * as Ramose from "@ramose/alchemy/db";
   import * as Schema from "effect/Schema";

   export const Todo = Ramose.Namespace("todo", {
     title: Ramose.Attr(Schema.String),
     done: Ramose.Attr(Schema.Boolean),
     createdAt: Ramose.Attr(Ramose.Instant),
   });

   export const Todos = Ramose.Catalog({ todo: Todo });
   ```

3. **Declare the peer.** Naming a database is all there is to creating one —
   there is no provisioning step. Point `main` at the published Worker
   package:

   ```ts title="resources.ts"
   import * as Ramose from "@ramose/alchemy";
   import * as Cloudflare from "alchemy/Cloudflare";

   const Store = Cloudflare.R2.Bucket("Store");
   const Transactor = Cloudflare.DurableObject("TransactorDO", {
     className: "TransactorDO",
   });
   const Replica = Cloudflare.DurableObject("QueryReplicaDO", {
     className: "QueryReplicaDO",
   });

   export const RamoseWorker = Cloudflare.Worker("Peer", {
     main: "@ramose/worker",
     compatibility: { date: "2025-06-01", flags: ["nodejs_compat"] },
     env: { STORE: Store, TRANSACTOR: Transactor, REPLICA: Replica },
   });

   export const Server = Ramose.Server("Ramose", { worker: RamoseWorker });
   ```

   ```ts title="alchemy.run.ts"
   import * as Ramose from "@ramose/alchemy";
   import * as Alchemy from "alchemy";
   import * as Cloudflare from "alchemy/Cloudflare";
   import * as Effect from "effect/Effect";
   import * as Layer from "effect/Layer";
   import { Server } from "./resources.ts";
   import { Todos } from "./src/schema.ts";

   export const TodosDb = Ramose.Database("todos", {
     server: Server,
     catalog: Todos,
   });

   export default Alchemy.Stack(
     "todos",
     {
       providers: Layer.mergeAll(Cloudflare.providers(), Ramose.providers()),
       state: Alchemy.localState(),
     },
     Effect.gen(function* () {
       const server = yield* Server;
       yield* TodosDb;
       return { peerUrl: server.url };
     }),
   );
   ```

4. **Connect from the app.** One `Ramose.connect` handle for the page: a
   plain object, nothing to dispose but `ramose.close()`. Your local peer has
   no token — pass nothing rather than an empty credential:

   ```ts title="src/db.ts"
   import * as Ramose from "@ramose/alchemy/db";
   import { Todos } from "./schema.ts";

   const token = import.meta.env.VITE_RAMOSE_TOKEN;

   const ramose = Ramose.connect({
     url: import.meta.env.VITE_RAMOSE_URL ?? "http://localhost:1337",
     token: token ? Ramose.token.static(token) : undefined,
   });

   export const db = ramose.db("todos", Todos);
   ```

   Ramose is built on [Effect](https://effect.website). Its API returns Effect
   values — descriptions of work — and nothing a `Db` returns needs an
   environment, so the shipped React hooks run them for you and `yield*`
   inside `db.transact` sequences the steps of a write. That is all the
   Effect the rest of this path needs.

5. **Write the query and the write.** Keep them in one module so the UI and
   any test drive the same code:

   ```ts title="src/todos.ts"
   import * as Ramose from "@ramose/alchemy/db";
   import type { Db } from "@ramose/alchemy/db";
   import { Todo, type Todos } from "./schema.ts";

   export type TodosDb = Db<typeof Todos>;

   export const todoShape = {
     id: Todo.id,
     title: Todo.title,
     done: Todo.done,
     createdAt: Todo.createdAt,
   } as const;

   export const todoQuery = Ramose.query(Todo)
     .orderBy(Todo.createdAt, "asc")
     .select(todoShape);

   export type TodoRow = Ramose.Row<typeof todoQuery>;

   export const addTodo = (db: TodosDb, title: string) =>
     db.transact(function* (tx) {
       const t = yield* tx.entity();
       yield* t.add(Todo.title, title);
       yield* t.add(Todo.done, false);
       yield* t.add(Todo.createdAt, new Date());
     });
   ```

6. **Render the list.** `useLive(db, todoQuery)` from
   [`@ramose/react`](/reference/react/) is the subscription; `useTransact().run`
   runs each write from its event handler:

   ```tsx title="src/App.tsx"
   import { useState } from "react";
   import { useLive, useTransact } from "@ramose/react";
   import { db } from "./db.ts";
   import { addTodo, todoQuery } from "./todos.ts";

   export const App = () => {
     const { rows, error } = useLive(db, todoQuery);
     const { run } = useTransact();
     const [title, setTitle] = useState("");
     if (error !== undefined) return <p>offline…</p>;
     if (rows === undefined) return <p>loading…</p>;
     return (
       <>
         <form
           onSubmit={(e) => {
             e.preventDefault();
             void run(addTodo(db, title)).then(() => setTitle(""));
           }}
         >
           <input value={title} onChange={(e) => setTitle(e.target.value)} />
           <button type="submit">Add</button>
         </form>
         <ul>
           {rows.map((row) => (
             <li key={row.id}>{row.title}</li>
           ))}
         </ul>
       </>
     );
   };
   ```

   The hook memoises `db.live(todoQuery)` on `[db, query]`, resets when the
   inputs change, and tears down by interrupting its fiber on unmount.

7. **Start the peer.** Leave this terminal running. Alchemy emulates R2 and
   both Durable Objects on your laptop — nothing is sent to Cloudflare.

   ```sh title="Terminal — the peer"
   npx alchemy dev
   ```

   The peer — the Worker that serves your databases — comes up on
   **:1337**. You will see something like:

   ```
   [Peer] ready at http://localhost:1337
   Done: 8 succeeded
   ```

   <details>
   <summary>If Alchemy asks you to log in</summary>

   Local miniflare still wants placeholder Cloudflare credentials, and an
   interactive login fails in CI-like environments. Prefix the command with:

   ```sh
   CI=1 ALCHEMY_STATE=local \
     CLOUDFLARE_ACCOUNT_ID=0123456789abcdef0123456789abcdef \
     CLOUDFLARE_API_TOKEN=x \
     npx alchemy dev
   ```

   The account id is a placeholder and the API token is the literal letter
   `x`. `ALCHEMY_STATE=local` keeps the whole stack on your machine, so
   nothing is billed. Each variable is only defaulted when unset, so set your
   own to override one.

   </details>

   :::note[A harmless-looking scare]
   When a tab closes you may see workerd print `The Workers runtime canceled
   this request because it detected that your Worker's code had hung`. That is
   the local emulator reaping a live-query socket, not a crash — the peer keeps
   serving.
   :::

8. **Start the app.** From a second terminal, in the same directory:

   ```sh title="Terminal — the app"
   VITE_RAMOSE_URL=http://localhost:1337 npm run dev
   ```

   Open `http://localhost:5173`. You should see a text box and an empty list.
   Type "buy milk", press add, and the row appears — the list re-renders
   without a refetch. Nothing in the app calls "reload" after a write.

   That is a live query. `db.live(todoQuery)` is a stream of rows; a write
   advances the connection's position in the database, and every standing
   query on that connection re-runs against the new position.

   Check the peer any time with `curl http://localhost:1337/health` — you
   want `{"ok":true,"service":"ramose",…}`.

   :::note[Two tabs, locally]
   On the local emulator writes do not propagate between isolates, so a second
   tab picks them up on reload. Your own tab always updates, because its own write
   moves its own connection forward. Against a deployed peer, every connected
   client updates.
   :::

9. **Deploy it (optional).** Switch the stack to real Cloudflare state (see
   [Deploy with Alchemy](/guides/deploy/)) and run:

   ```sh title="Terminal"
   npx alchemy deploy
   ```

   This one needs real credentials — a `CLOUDFLARE_API_TOKEN` and your
   `CLOUDFLARE_ACCOUNT_ID`. Read [Before
   production](/guides/before-production/) first: a freshly deployed peer
   accepts requests from anyone until you configure a policy.

</Steps>

Ctrl-C in the peer terminal stops the database. Ctrl-C in the app terminal
stops Vite.

administrator. That is right for a laptop and wrong for the internet.
