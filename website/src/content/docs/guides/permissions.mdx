Policy is deployed with each catalog and denies by default. Read rules decide which facts exist in a principal's filtered database. Invoke rules decide which exact operations the principal may attempt.

## Compile policy with the catalog

```ts
import * as Ramose from "ramose"

const P = Ramose.Policy

export const policy = P.compileReadAuthorization({
  schema: ProjectSchema,
  classes: ["member", "admin"],
  claims: ["org"],
  principal: { entity: User.authId },
  rules: [
    P.read(Task).when(P.hasClass("member")),
  ],
})
```

The compiler produces inert schema-checked policy data. Deployment binds it to the exact catalog and rejects unknown fields, invalid paths, incompatible targets, unbounded structures, and undeclared claims.

## Allow an entity

```ts
P.read(Task).when(P.hasClass("member"))
```

Multiple allows for the same focus combine with OR. A deny overrides allows at that focus:

```ts
P.read(Task).deny(P.hasClass("suspended"))
```

## Use the resource and principal

```ts
P.read(Task).when((task) =>
  P.any(
    task.owner.eq(P.me),
    task.project.members.contains(P.me),
    P.hasClass("admin"),
  ),
)
```

`me` is the principal entity resolved through the configured unique field. `subject` is the JWT subject string. `claim(name)` reads a declared stable claim. Resource relation traversal is bounded and must remain within the catalog.

Prefer database-backed membership for rapidly changing access and claims for stable deployment-wide context. A token is identity input, not a database selector.

## Narrow a field

```ts
P.read(Task).when(P.hasClass("member")),
P.read(Task.privateNote).when(P.hasClass("admin")),
```

The field rule narrows its parent. A client asking for `privateNote` receives it only for admins; the field is absent for others. Hidden refs hide the whole edge rather than revealing an inaccessible target id.

## Author trait rules

```ts
P.read(Commentable).when(P.hasClass("member"))
```

Trait rules apply to the trait fields on readable composers. They do not reopen an entity hidden by its concrete rule. This makes reusable capability policy possible without weakening concrete domains.

## Grant exact operations

```ts
const ops = Task[Ramose.OwnedOperations]

P.invoke(ops.createTask).when(P.hasClass("member"))
P.invoke(ops.setDone).when(P.hasClass("member"))
P.invoke(ops.delete).when(P.hasClass("admin"))
```

Invoke expressions are principal-only: classes, subject, and claims. Targeted operations separately require a visible compatible target. If an update is only valid for a resource owner, express that invariant as a narrower domain operation until target-aware grant predicates exist; do not expose a broad generated update.

## Graph access needs no enter rule

A readable Graph row and required Graph fields make the child discoverable and openable. The child policy then filters its contents. Every ancestor is reauthorized for long-lived output; an inaccessible ancestor stops descendant synchronization.

## Test observable behavior

For each role, test visible rows, fields, relations, trait roots, graph paths, operations, history, counts, ordering, limits, errors, and revocation. Compare hidden and nonexistent cases. The security contract includes what callers cannot infer, not just which successful request returns 200.
