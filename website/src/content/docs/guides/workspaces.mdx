A database is a name. Naming it creates it. This page is for anyone who wants each customer or team in its own database, from the browser (Reef) or from a Worker.

## Name it, install it

A **workspace** is one customer's isolated data, one database ([glossary](/concepts/glossary/#workspace)). In Reef you make one by typing a name and clicking Create: the name becomes a slug, and the slug becomes the database.

<Shot src="/reef/workspace-create.png" alt="Reef's workspace picker: a New workspace form with Tidepool typed in and, beneath the field, a preview of the ramose.db install call it will run" caption="Typing a name previews the call; Create runs it. The database exists after that first write." code="examples/reef/src/app/screens/WorkspacesScreen.tsx:384-392" />

*Writes are named operations (`await db.run(…)`). Effect is an [advanced hatch](/concepts/effect/).*

```ts title="examples/reef/src/app/ramose.ts#open-workspace-token · examples/reef/src/app/ramose.ts#open-workspace-provision"
  const token =
    options?.token ??
    Ramose.token.jwt(async () => {
      const { authClient } = await import("./auth.ts");
      return authClient.ramose.token({ db: slug });
    });
  await token.claims();

    const connect = options?.connect ?? Ramose.connect;
    const ramose = connect({
      url: options?.url ?? RAMOSE_URL,
      token,
      fetch: options?.fetch,
      webSocket: options?.webSocket,
    });
    try {
      await provisionWorkspace(ramose.db(slug, Reef));
    } finally {
      await ramose.close();
    }
```

`ramose.db(slug, Reef)` is a pure call: no network, no create step. The first write makes the database real, and Reef's first write **installs** the schema — writes it in as an ordinary write ([glossary](/concepts/glossary/#install)) — then seeds labels. The peer upserts your `user` row (`sub`, `role`, name, email) at session establishment:

```ts title="examples/reef/src/app/mutations.ts#provision-workspace"
export const provisionWorkspace = (db: ReefDb) =>
  db.run(provisionWorkspaceOp, {}).then(() => undefined);
```

`db.install()` is safe to run twice: an already-deployed schema is a silent no-op, including from a member token. A new ident still requires a `schemaClasses` class — Reef's first install runs under the creator's owner token.

## What that buys you

- **No fleet to manage.** One deployed server serves every name — one thing to deploy, not one per customer.
- **Isolation by construction.** Every name gets its own prefix in storage and its own **writer**, the one thing per database that commits writes, in order ([glossary](/concepts/glossary/#writer)). Nothing done to one database touches another.

## What counts as a name

Letters, digits, `.`, `_`, `-`; up to 64 characters; starting with a letter or digit. `Ramose.isDatabaseName(name)` (and `Ramose.DATABASE_NAME_RE`) lets a "create workspace" form check first; a bad name fails the first call with `InvalidRequest` and never leaves the browser. Reef adds a stricter slug rule on top (`examples/reef/src/domain/shared.ts:57-60`).

## Two doors to install the schema

Something must install the schema before the first real read or write.

**At deploy** — for databases you know by name. The todos app declares one:

```ts title="examples/todos/resources.ts"
export const Server = Ramose.Server("Ramose", {
  databases: { todos: Todos },
});
```

**At creation** — for names that appear at run time. Reef calls `db.install()` from the browser under the creator's owner token (`schemaClasses`, not a bypass class); a Worker does the same at sign-up.

`databases:` on Server for the databases your app always has; `db.install()` when users create them. Standalone `Ramose.Database` is the same install for runtime-provisioned names that are still declared at deploy. Never per request.

## One token per workspace

Under a policy, a sign-in token names one database in its `ramose.db` claim. A token for `coral-reef-divers` cannot open `kelp-forest`; the answer is `Unauthorized`. Opening another workspace means another token, so Reef gives `RamoseProvider` a `key={slug}` and the client is rebuilt (`examples/reef/src/app/App.tsx:191-203`). See [Sign in and roles](/guides/sign-in/#tokens-refresh-themselves).

## From a Worker

Your own Worker holds a typed client and does the same at sign-up:

```ts title="examples/kv-style/app.ts#create-tenant"
    const createTenant = (tenantId: string) =>
      Effect.gen(function* () {
        const report = yield* ramose.db(tenantId, Movies).effect.install();
        return yield* HttpServerResponse.json({ tenant: tenantId, t: report.t });
      });
```

Every later request is `ramose.db(tenantId, Movies)` again, pure, per request. How the Worker gets `ramose`: [Use it from a Worker](/guides/workers/).

## The one limit

One database has one writer: writes land in order, one **version number** `t` each ([glossary](/concepts/glossary/#version-number)). In our benchmark (`bench/RESULTS.md` in the repo) one database sustained a few hundred writes per second on Cloudflare — 166–879 per second depending on client count. Past that you split across databases: a function call, not a deployment. There are no queries across databases; that is the price of the split.
