This page is everything about the **schema** — your data model as one TypeScript value ([glossary](/concepts/glossary/#schema)). It is for anyone who has built the first app and wants to model real data.

## Three pieces, and that is the whole vocabulary

- **`Ramose.string()`** (and the other value shorthands) declare one **field** — a named, typed slot ([glossary](/concepts/glossary/#field)).
- **`Ramose.Entity`** groups fields into a **record type** — a kind of record, like a table ([glossary](/concepts/glossary/#record-type)). `Issue.title` is `:issue/title` on the wire; you always write `Issue.title`.
- **`Ramose.Schema`** collects record types into the schema a database installs.

A raw [Effect Schema](https://effect.website) is still accepted as the advanced form (`Ramose.Field(schema)`); app schemas do not import it.

## Reef's schema, annotated

Reef's whole data model is 76 lines. The parts that matter:

```ts title="examples/reef/src/domain/schema.ts:14-33"
export const User = Ramose.Entity("user", {
  sub: Ramose.string({
    unique: "upsert",
    doc: "Better Auth user id — the JWT `sub`; the policy resolves principals through it",
  }),
  role: Ramose.string({
    doc: "Policy class, materialized by the peer from the JWT at session establishment",
  }),
  name: Ramose.string({
    doc: "Display name, stamped by the peer from ramose.attrs.name",
  }),
  email: Ramose.string({
    doc: "Email, stamped by the peer from ramose.attrs.email",
  }),
});

export const Label = Ramose.Entity("label", {
  name: Ramose.string({ unique: "upsert" }),
  color: Ramose.string(),
});
```

```ts title="examples/reef/src/domain/schema.ts:38-54"
export const Issue = Ramose.Entity("issue", {
  title: Ramose.string(),
  description: Ramose.string(),
  status: Ramose.Enum(STATUSES),
  /** 0 none · 1 low · 2 medium · 3 high · 4 urgent. */
  priority: Ramose.int(),
  /** Fractional order inside a column; drag-and-drop writes midpoints. */
  rank: Ramose.float(),
  createdAt: Ramose.timestamp(),
  creator: Ramose.Ref(User),
  assignee: Ramose.Ref(User),
  labels: Ramose.Field.many(Ramose.Ref(Label)),
  /** Admin-only field — the policy narrows its `read` (see policy.ts). */
  privateNote: Ramose.string({
    doc: "visible to the admin class only",
  }),
});
```

`Comment` (`schema.ts:48-53`) has the same shape, and `Reef = Ramose.Schema({ user, label, issue, comment })` (`schema.ts:55-60`) collects the four.

| field | what it means |
| --- | --- |
| `user.sub` | The account id from the sign-in system. `unique: "upsert"` = one **record** ([glossary](/concepts/glossary/#record)) per person, and you can look a user up by it. Used by permissions later. |
| `issue.priority`, `issue.rank` | A whole number (`Ramose.int()`); a double (`Ramose.float()`). |
| `issue.creator` → `user` | A **reference** — a typed foreign key ([glossary](/concepts/glossary/#reference)). Permissions fill it in for you. |
| `issue.labels` → `label` | A *set* of references — no join table. |
| `issue.privateNote` | Admin-only text; the policy masks it for everyone else. |

Every record type also gets an `id` field for free (`Issue.id`).

## Value types

| shorthand | stores |
| --- | --- |
| `Ramose.string()` · `Ramose.boolean()` | text · true/false |
| `Ramose.float()` | a double (`Issue.rank`) |
| `Ramose.int()` | a whole `number`, stored as a long (`Issue.priority`) — it is a JavaScript number, so nothing above 2⁵³ is exact |
| `Ramose.timestamp()` | a point in time — you pass and receive a `Date` |
| `Ramose.Enum(["low", "med", "high"])` | one of those strings |
| `Ramose.Ref(User)` · `Ramose.Ref.self` | a reference to a record of that type · of the same type |
| `Ramose.Ref(() => Other)` | the same, as a thunk — only when `Other` is declared later |
| `Ramose.uuid()` | a canonical UUID `string` |
| `Ramose.bytes()` | binary data (`Uint8Array`) |

Shorthands take the same option bag as `Field` (`unique`, `doc`, …) and compose with `Field.many` / `Field.unique`. A raw Effect Schema is the advanced form: `Ramose.Field(schema)` — `String` / `Number` / `Boolean` infer a value type; anything else must pass `{ valueType }` or the field types `valueType` as `undefined` (install then fails). Branded schemas (`Long`, `Instant`, `Uuid`, `Bytes`) stay as that advanced-form vocabulary — `Field(Ramose.Uuid)` row types are `string`. `UuidString` is deprecated for `Uuid`.

## Options

| option | default | effect |
| --- | --- | --- |
| `unique` | none | `"upsert"` makes the field a **unique key** ([glossary](/concepts/glossary/#unique-key)): one record per value; `[User.sub, "…"]` looks it up. `"strict"` rejects a colliding write. |
| `cardinality` | `"one"` | **one value or many** ([glossary](/concepts/glossary/#one-or-many)): `"many"` makes the field a set — a second value adds rather than replaces |
| `index` | true when `unique` is set | keeps a value-ordered index, so you can look a record up by value |
| `owned` | `false` | the referenced record belongs to its parent and is deleted with it. Its `.reverse` is one record, not an array — a component has at most one owner |
| `doc` | none | a description stored with the field |
| `valueType` | inferred | the stored type, when it cannot be inferred |

## References between records

`Ramose.Ref(User)` points at another record. Naming the target lets a query hop through it (`Query.follow(Issue.assignee)`) or backwards (`Query.backlink(Issue.creator)` — the issues that point at this user), and lets a shape nest (`Issue.assignee.select({ … })`) or read backwards (`Issue.creator.reverse.select({ … })`). Write `Ref(() => Other)` only when the target is declared later (a cycle).

## Types flow out of the schema

Nothing downstream needs a type annotation. Reef's board row is inferred:

```ts title="examples/reef/src/domain/queries.ts:90-91"
/** One row of {@link boardQuery} — inferred from the query, never restated. */
export type BoardRow = Ramose.Row<typeof boardQuery>;
```

`BoardRow["priority"]` is a `number`, `createdAt` a `Date`, `assignee` `{ id; name } | undefined`. Writes are checked too: `issue.set(Issue.priority, "high")` does not compile. Your UI types are your database types; they cannot drift.

## Where the schema gets installed

`ramose.db(name, Reef)` names a database without touching the network, so something must **install** the schema — an ordinary write, safe to repeat ([glossary](/concepts/glossary/#install)). Two doors.

At deploy, for a database you know up front (the todos app):

```ts title="examples/todos/resources.ts"
export const Server = Ramose.Server("Ramose", {
  databases: { todos: Todos },
});
```

From the app, for names created at runtime — how Reef makes a workspace:

```ts title="examples/reef/src/app/mutations.ts:29-31"
export const provisionWorkspace = (db: ReefDb) =>
  Effect.gen(function* () {
    yield* db.install();
```

Which door, and why: [One database per customer](/guides/workspaces/#two-doors-to-install-the-schema).

## Changing a schema later

Adding a field or a record type is another install; the app keeps running. There is no destructive migration to fear, because Ramose never rewrites a **fact** — one statement about one record's field ([glossary](/concepts/glossary/#fact)). Old data keeps the field it was written with, reads of the past keep working, and removing a field from the schema does not delete the facts that used it.

Three changes are *not* guarded: a field's value type, whether it holds one value or many, and whether it is a unique key. Existing data is neither re-typed nor checked — add a new field instead. Dropping an option is quieter still: nothing goes over the wire, so the old setting stays. Under a policy, only the `admin` role may change the schema.
