The exact surface of `ramose/react`, one section per export. This page is for React developers who have read [Live queries](/guides/live-queries/) and want the signatures.

*New here? Start with [Getting started](/getting-started/quickstart/).*

```tsx
import { RamoseProvider, useDb, useLiveQuery, useQuery, useLivePull, usePull, useBasis, useTransact, errorMessage } from "ramose/react";
```

Hooks only, no UI. They reach the Ramose server through one client. Read hooks take a `db` explicitly, so they work with `db.asOf(t)` and `db.history` too. The **Ramose server** is the one Cloudflare Worker that serves all your databases.

Every read hook returns the same `Read<A, E>`: `data`, a plain tagged `error`, `status` / `isLoading`, the basis `t` the rows were read at, and `refetch()`. Names say liveness: `useLiveQuery` / `useQuery`, `useLivePull` / `usePull`. Result types exported alongside the hooks: `Read`, `ReadStatus`, `Transact`, `RunResult`, `RamoseProviderProps`.

## RamoseProvider

```tsx title="examples/reef/src/app/App.tsx#ramose-provider"
          <RamoseProvider
            key={open.workspace.slug}
            url={RAMOSE_URL}
            token={open.workspace.token}
          >
```

`RamoseProvider(props: ClientOptions & { children })` — owns one **client** ([glossary](/concepts/glossary/#client)) made with `Ramose.connect`, and closes it on unmount or when `url` / `token` / `fetch` / `webSocket` change.

- `token` must be a stable **token source** ([glossary](/concepts/glossary/#token-source)) — module scope or `useMemo`, never built inline.
- One customer per client: switch workspaces with React's `key`, as Reef does.

## useDb

```tsx title="examples/reef/src/app/screens/BoardScreen.tsx#use-db"
  const db = useDb(slug, Reef);
```

`useDb(name, schema): Db<C>` — `client.db(name, schema)` from the nearest provider, kept stable on `[client, name, schema]`. Pass a module-scope schema. Throws outside a provider.

## useLiveQuery

```tsx title="examples/todos/src/App.tsx#todo-list"
const TodoList = () => {
  const { data, error } = useLiveQuery(db, todoQuery);
  if (error !== undefined) return <p>offline…</p>;
  if (data === undefined) return <p>loading…</p>;
  return (
    <ul>
      {data.map((row) => (
        <TodoRowView key={row.id} row={row} />
      ))}
    </ul>
  );
};
```

`useLiveQuery(db, query): Read<Out, QueryError>` — a **live query** as React state: it re-runs whenever the database changes ([glossary](/concepts/glossary/#live-query)). Needs no provider. Put changing values in the query (`where({ issue: issueId })`). Same literals share a subscription; a changed literal resubscribes.

- `data` is `undefined` until the first answer, and again right after `db` or `query` change.
- `error` is a *terminal* failure only (`InvalidRequest`, `DatabaseNotFound`, `Unauthorized`, `QueryBudgetExceeded`); network trouble is retried in place. On `db.asOf(t)` the query runs once and the data stays.
- `t` is the basis those rows were read at. `status` / `isLoading` cover the first answer; later emissions are not a load. `refetch()` re-reads once without tearing the subscription down.
- `key={row.id}`: a selected `id: X.id` is a plain `number`.

A second form, `useLiveQuery(sub)`, drains a `Subscription` you built yourself (`db.live(q)`, `db.livePull(...)`) with the same result shape.

## useQuery

```tsx title="examples/reef/src/app/screens/BoardScreen.tsx#use-query"
  const past = useQuery(t === undefined ? db : db.asOf(t), boardQuery);
```

`useQuery(db, query): Read<Out, QueryError>` — one `db.query` per view / lowered-AST pair (the same structural key `useLiveQuery` uses). A render-fresh factory with the same literals does not re-run. While a new run is loading the previous `data` stays, so a time-travel slider never flashes empty; a slower older answer never overwrites a newer one. `refetch()` re-issues the same run.

## useLivePull

```tsx title="examples/reef/src/app/components/IssueDetail.tsx#use-pull-extra"
  const extra = useLivePull(db, issueId, issueExtraShape).data ?? null;
```

`useLivePull(db, subject, shape): Read<Pull | null>` — one record, live. `data` is the record or `null` (missing, deleted, or a required field hidden from you). A branded `row.id` (or a number) inline is fine; hoist the shape.

## usePull

`usePull(db, subject, shape): Read<Pull | null>` — one `db.pull`, same `Read` shape. Previous `data` stays while a later subject is in flight.

## useBasis

```tsx title="examples/reef/src/app/screens/BoardScreen.tsx#use-basis"
  const maxT = useBasis(db);
```

`useBasis(db): number | undefined` — the **version number** this view reads at ([glossary](/concepts/glossary/#version-number)), from `session.t` on a live view (no `GET /info` per update). Reef uses it as the slider's upper bound. `useBasis(db.asOf(t))` answers `t` at once with no request.

## useTransact

```tsx title="examples/reef/src/app/screens/BoardScreen.tsx#use-transact"
  // Every write is one `run(...)`; a policy denial (or any DbError) becomes
  // a toast — enforcement is server-side, the UI is only a hint.
  const { run } = useTransact({
    onError: (error) => toast("error", errorMessage(error)),
  });
```

```tsx title="examples/todos/src/App.tsx#todo-row-transact"
  const { run } = useTransact();
```

`useTransact<E>(options?): { run, pending, error, clearError }` — pending / error helper for a promise from an event handler. Not the write API: that is `db.run`. Typical call is `run(moveIssue(db, id, status, rank))`. Needs no provider and takes no `db`. `error` is the tracked `E`.

- `run(work): Promise<{ ok: true, value } | { ok: false, error }>` — resolves instead of throwing, so `onClick={() => void run(...)}` is safe. Failure lands on `error` / `onError`.
- `pending` is `true` while any run is in flight; `error` holds the last failure until a run succeeds or `clearError()`; `onError` fires per failure.

## errorMessage

```ts
errorMessage(e); // e.message ?? e._tag ?? String(e)
```

`errorMessage(error: unknown): string` — the one-liner for a toast; a policy denial shows the server's message, e.g. `remove denied on :issue/status`.

## Rules

- **Stable token source.** Build it once per sign-in, not per render.
- **Inline query values.** `useLiveQuery` and `useQuery` key on the lowered AST — `useLiveQuery(db, Query.from(Comment).where({ issue: issueId }))` is the spelling. Same literals share a subscription / one-shot run; a changed literal resubscribes or re-runs. Hoist shapes for `useLivePull` / `usePull`. `db`, `db.asOf(t)` and `{ id }` subjects are compared by value, so inline is fine.
- **One client per customer.** Remount the provider with `key={slug}` when the workspace changes.
- **`key={row.id}`** in lists; the id is a `number`.
- **`error` is the tagged failure.** Every hook reports the class itself, so `errorMessage(error)` works on every hook.
