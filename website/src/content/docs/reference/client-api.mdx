Every exported name of `ramose/db`, with its signature and a short example. This page is for people who have built the first app and want the exact shape of every call to the Ramose server. The **Ramose server** is the one Cloudflare Worker that serves all your databases.

*New here? Start with [Getting started](/getting-started/quickstart/).*

## Rules of thumb

- **A `db` is a value.** `ramose.db(name, schema)` makes no request, and `asOf` and `history` are pure too.
- **A write is all-or-nothing** — one **write** is one all-or-nothing change ([glossary](/concepts/glossary/#write)). It returns a `TxReport`; `report.dbAfter` reads your own write with no second round trip.
- **Reads shrink, writes fail.** Fields you may not read are absent; a write you may not make is `Unauthorized`.
- **Live queries need a WebSocket.** `db.live` and `db.livePull` retry network trouble on their own.
- **Setup mistakes throw, they are not errors.** A malformed URL or missing `fetch` throws from `connect`; a `DbError` is always about a request.
- **Install is explicit.** `db.install()` writes the schema and is safe to run twice; naming a database never creates one.

*Ramose is built on [Effect](https://effect.website). In React you rarely see it — the hooks run it for you; inside `db.transact` you write `yield*`. ([Effect in five minutes](/concepts/effect/))*

## Imports

`ramose/db` is the portable half: browser, Worker, Node, tests. `ramose` re-exports all of it and adds the deploy half.

```ts
import * as Ramose from "ramose/db"; // schema, connect, db, query, errors
import * as Ramose from "ramose";    // the same, plus Server, Databases, layer, Policy, claims
```

| entry | runtime names |
| --- | --- |
| `ramose/db` | `Field` · `Entity` · `Schema` · `string` · `boolean` · `int` · `float` · `timestamp` · `uuid` · `bytes` · `Enum` · `Ref` · `Instant` · `Uuid` · `Long` · `Bytes` · `stored` · `Q` · `Query` · `all` · `again` · `values` · `EntityId` · `Operation` · `Operations` · `PrefixHalt` · `connect` · `token` · `DATABASE_NAME_RE` · `isDatabaseName` · `isDatabaseError` · `PolicyError` · `OperationRejected`, the nine `DbError`s below, and `NotOne` |
| `ramose` (adds) | `Server` · `Database` · `Databases` · `layer` · `asRead` · `PEER_COMPAT` · `providers` · `Providers` · `Policy` · `DEFAULT_JWT_MAX_TTL` · `claims` · `errorToHttp` · `errorResponse` — see [Deploy](/guides/deploy/#reference-the-ramose-resources) and [Policy](/reference/policy/) |

Two more entries carry the server Worker and the React hooks: `ramose/worker` is what `main` points at ([Deploy](/guides/deploy/)), and `ramose/react` is the hooks ([React](/reference/react/)). Sign-in adds `ramose/better-auth` and `ramose/better-auth/client` ([Sign in](/guides/sign-in/)).

### Effect comes with Ramose

App schemas use `Ramose.string()` and the other shorthands — they do not import Effect. The hatch path (`ramose/db/effect`, `Ramose.Field(schema)`, operation codecs) still uses Effect Schema. `effect` is a dependency of `ramose`, not something you install beside it; two copies in one tree produce mutually unassignable types. Declare `effect` in your own `package.json` only at a version that agrees with Ramose's.

One subpath lets you avoid naming it at all, which is what a resolver that refuses undeclared imports (pnpm without hoisting, Yarn PnP) needs:

```ts
import { Schema, Effect, Layer, Stream, Redacted, pipe } from "ramose/effect";
```

It re-exports the module instances `effect` itself exports, so the two spellings are interchangeable — in the same file, and across a package boundary.

## Schema

The **schema** — your data model as one TypeScript value ([glossary](/concepts/glossary/#schema)) — is built from three constructors.

```ts title="examples/todos/schema.ts#todo-schema"
import * as Ramose from "ramose/db";

export const Todo = Ramose.Entity("todo", {
  title: Ramose.string(),
  done: Ramose.boolean(),
  createdAt: Ramose.timestamp(),
});

export const Todos = Ramose.Schema({ todo: Todo });
```

**`Ramose.Entity(name, fields)`** — a **record type**, a named group of fields like a table ([glossary](/concepts/glossary/#record-type)). The result carries every field as a handle (`Todo.title`, full name `:todo/title`) plus `Todo.id`, the record's numeric **id** ([glossary](/concepts/glossary/#id)), usable in `where`, `select` and `orderBy`.

**Value shorthands** — `string()`, `boolean()`, `int()`, `float()`, `timestamp()`, `uuid()`, `bytes()`, `Enum([...])`, `Ref(Entity)`. Each accepts the option bag and composes with `Field.many` / `Field.unique`.

```ts
Ramose.string()
Ramose.string({ unique: "upsert" })
Ramose.Field.unique(Ramose.string(), "upsert")
Ramose.Field.many(Ramose.Ref(Label))
Ramose.Enum(["low", "med", "high"])
```

**`Ramose.Field(schema, options?)`** — the advanced form: a raw Effect Schema as a **field** ([glossary](/concepts/glossary/#field)). When the Schema is not a branded helper or a `String` / `Number` / `Boolean` AST, wrap it with `stored(schema, vt)`.

```ts
import { Schema } from "ramose/effect";
Ramose.Field(Schema.String)
Ramose.Field(Ramose.stored(Schema.Literals(["todo", "done"]), "string"))
Ramose.Field(Ramose.Ref(Label), { cardinality: "many" })
```

| option | values | default |
| --- | --- | --- |
| `cardinality` | `"one"` · `"many"` | `"one"` |
| `unique` | `"upsert"` · `"strict"` | — |
| `index` | `boolean` | `true` when `unique` is set, else `false` |
| `owned` | `boolean` | `false` |
| `doc` | `string` | — |

**`Ramose.Schema({ key: Entity, … })`** — the whole schema. The key (`todo`) is what a policy's `ns: { todo: … }` refers to. Type-level helpers: `Ramose.Schema.Any` (the bound for generic code), `typeof Todos`.

| shorthand | TypeScript value | stored as |
| --- | --- | --- |
| `Ramose.string()` | `string` | string |
| `Ramose.boolean()` | `boolean` | boolean |
| `Ramose.float()` | `number` | double |
| `Ramose.int()` | a whole `number` (a JavaScript double, so nothing above 2⁵³ is exact) | long |
| `Ramose.timestamp()` | `Date` | instant |
| `Ramose.uuid()` | canonical uuid `string` | uuid |
| `Ramose.bytes()` | `Uint8Array` | bytes |
| `Ramose.Enum(["low", "med"])` | `"low" \| "med"` | string |
| `Ramose.Ref(User)` | `number` (the target's id); enables nested `.select({ … })` and `.reverse` in shapes, `Query.follow` / `Query.backlink` in queries | ref |
| `Ramose.Ref(() => Other)` | the same, thunk form for cycles | ref |
| `Ramose.Ref.self` | a reference to the same record type | ref |
| `Ramose.Ref` (bare) | `number`, untargeted | ref |

Branded schemas (`Long`, `Instant`, `Uuid`, `Bytes`) stay as the advanced-form vocabulary (`Field(Ramose.Uuid)`). `Field(Ramose.Uuid)` row types are `string`. `stored(schema, vt)` brands a custom Schema with a matching storage form.

```ts title="examples/reef/src/domain/schema.ts#issue-entity"
export const Issue = Ramose.Entity("issue", {
  title: Ramose.string(),
  description: Ramose.string(),
  status: Ramose.Enum(STATUSES),
  /** 0 none · 1 low · 2 medium · 3 high · 4 urgent. */
  priority: Ramose.int(),
  /** Fractional order inside a column; drag-and-drop writes midpoints. */
  rank: Ramose.float(),
  createdAt: Ramose.timestamp(),
  creator: Ramose.Ref(User),
  assignee: Ramose.Ref(User),
  labels: Ramose.Field.many(Ramose.Ref(Label)),
  /** Admin-only field — the policy narrows its `read` (see policy.ts). */
  privateNote: Ramose.string({
    doc: "visible to the admin class only",
  }),
});
```

## Client

**`Ramose.connect(options): Client`** — the **client** talks to the server for one page and hands out `db` handles ([glossary](/concepts/glossary/#client)).

```ts
interface ClientOptions {
  url: string;                       // the Ramose server's base URL
  token?: TokenSource | Effect<Redacted<string>, DbError>;
  fetch?: typeof fetch;              // defaults to the ambient fetch
  webSocket?: typeof WebSocket;      // defaults to the ambient WebSocket; needed for live
}
interface Client {
  db<C>(name: string, schema: C): Db<C>;   // pure: no request
  close(): Promise<void>;                   // safe to call twice; reads fail after it
}
```

```ts title="examples/reef/src/app/ramose.ts#open-workspace-token"
  const token =
    options?.token ??
    Ramose.token.jwt(async () => {
      const { authClient } = await import("./auth.ts");
      return authClient.ramose.token({ db: slug });
    });
  const cls = ((await token.claims()).ramose?.class ?? "viewer") as RamoseClass;
```

**`Ramose.token.static(value)`** and **`Ramose.token.jwt(mint, options?)`** — the two **token sources** ([glossary](/concepts/glossary/#token-source)). `jwt` calls `mint` on first use, shares one in-flight mint, and re-mints within `refreshMargin` (default 2 minutes) of the token's `exp`. `mint` may resolve to the token string or to `{ token }`. A thrown `Unauthorized` passes through; any other throw becomes `NetworkError`.

```ts
const source = Ramose.token.static(import.meta.env.VITE_RAMOSE_TOKEN);
const source = Ramose.token.jwt(() =>
  fetch("/api/auth/ramose/token", { method: "POST", body }).then((r) => r.json()),
);
source.claims();      // decoded, NOT verified — UI hints only
source.invalidate();  // forget the cached token (sign-out)
```

**`Ramose.Databases(Server)`** and **`Ramose.layer`** — the server-side client for a Worker or Action. Provide `Ramose.layer`; the handle has no `live` / `livePull`. The portable Effect hatch (`layer({ url, token })`, `yield* Databases`) lives on `ramose/db/effect`.

```ts
const ramose = yield* Ramose.Databases(Server);   // provide Ramose.layer
const db = ramose.db("todos", Todos);
```

**`Ramose.DATABASE_NAME_RE`** / **`Ramose.isDatabaseName(name)`** — the **database name** rule ([glossary](/concepts/glossary/#database-name)): `/^[a-zA-Z0-9][a-zA-Z0-9._-]{0,63}$/`. A bad name never reaches the server; every call on it fails `InvalidRequest`.

```ts
if (!Ramose.isDatabaseName(slug)) throw new Error("letters, digits, . _ - only");
```

## Db

`ramose.db(name, schema)` returns a `Db`. `db.asOf(t)` and `db.history` return a `ReadDb` — everything below except `principal`, `run` and `install`.

**`db.query(query): Promise<Out>`** — run a query once. Put values in the query (`where({ title })`). The result is the query's terminal: the rows array, one row (or `null`) after `q.one()` / `q.oneOrFail()` (`oneOrFail` fails with `NotOne`), a `{ rows, cursor }` page after `q.after(cursor)`. The hatch is `db.effect.query`.

```ts
const who = await db.principal();
const myEid = who.eid;
const people = await db.query(peopleQuery);
```

**`db.live(query): Stream<Rows, QueryError>`** — a **live query**: it re-runs whenever the database changes and emits new rows ([glossary](/concepts/glossary/#live-query)). Identical results are not re-emitted. Network trouble is retried in place; the stream fails only on `InvalidRequest`, `DatabaseNotFound`, `Unauthorized`, `QueryBudgetExceeded` or `NotOne`. On `asOf(t)` or `history` it emits once and completes. In React use [`useLive(db, query)`](/reference/react/#uselive).

```ts
const stream = db.live(boardQuery);   // Stream<BoardRow[], DbError>
```

**`db.pull(subject, shape): Effect<Pull | null, DbError>`** — read one record ([Pull](#pull) below).

```ts title="examples/todos/src/todos.ts"
export const pullTodo = (db: TodosDb, eid: TodoEid) =>
  db.pull(eid, {
    title: Todo.title,
    done: Todo.done,
    createdAt: Todo.createdAt,
  });
```

**`db.livePull(subject, shape): Stream<Pull | null, DbError>`** — the live form; a deleted record emits `null` and the stream stays open.

```ts
const stream = db.livePull(issueId, issueExtraShape);
```

**`db.basis(): Effect<{ t: number }, DbError>`** — the **version number `t`** this view reads at ([glossary](/concepts/glossary/#version-number)); one request on a live view, no request on `asOf(t)`.

```ts
const { t } = yield* db.basis();
```

**`db.asOf(t): ReadDb`** — the database as it was right after write `t`. `t` is a version number, not a `Date`. Pure.

```ts title="examples/kv-style/app.ts"
        const beforeRows = yield* db.asOf(report.t - 1).query(namesQuery);
        const before = beforeRows.map((r) => r.name);
```

**`db.history: ReadDb`** — a view that includes facts that were later removed. Pure.

```ts title="examples/reef/src/app/screens/BoardScreen.tsx"
  const everything = useQuery(db.history, everyIssueEverQuery);
```

**`db.principal(): Effect<{ eid: Eid | null; class: string }, DbError>`** — who this connection is: the **signed-in user's** record ([glossary](/concepts/glossary/#signed-in-user)) and role. The peer upserts that row at session establishment, so a signed-in caller has an `eid` once the principal attr is deployed. `eid` stays `null` for anonymous and service callers; `class` is `"admin"` on a server with no policy.

```ts
const me = yield* db.principal();   // { eid: 42 | null, class: "member" }
```

**`db.transact(function* (tx) { … }): Effect<TxReport, DbError | E>`** — one write. The body is a generator; `yield*` each step. A failure inside sends nothing.

```ts title="examples/todos/src/todos.ts"
export const addTodo = (db: TodosDb, title: string) =>
  db.transact(function* (tx) {
    const t = yield* tx.entity();
    yield* t.set(Todo.title, title);
    yield* t.set(Todo.done, false);
    yield* t.set(Todo.createdAt, new Date());
  });

export const setDone = (db: TodosDb, eid: TodoEid, done: boolean) =>
  db.transact(function* (tx) {
    yield* tx.set(eid, Todo.done, done);
  });

export const deleteTodo = (db: TodosDb, eid: TodoEid) =>
  db.transact(function* (tx) {
    yield* tx.delete(eid);
  });
```

**`db.install(): Effect<TxReport, DbError>`** — **install** the schema into this database as one write; safe to repeat ([glossary](/concepts/glossary/#install)). Under a policy only `admin` may run it.

```ts title="examples/reef/src/app/mutations.ts"
  Effect.gen(function* () {
    yield* db.install();
```

## Transactions

App writes go through `db.run`. The hatch `db.effect.transact` still takes a `tx`; `tx.entity()` gives a `TxHandle`. `set` / `remove` / `delete` write one field at a time; `put` is the entity-level write.

```ts
interface Tx<C> {
  entity(): Effect<TxHandle<C>>;                 // a new record
  entity(id: TxEntity<C>): Effect<TxHandle<C>>;  // an existing one
  put(entity, attrs): Effect<TxHandle<C>>;       // create
  put(entity, id, attrs): Effect<TxHandle<C>>;   // write that id (mints if new)
  set(e: TxEntity<C>, field, value): Effect<void>;
  remove(e: TxEntity<C>, field, value?): Effect<void>;
  delete(e: TxEntity<C>): Effect<void>;
}
interface TxHandle<C> { eid; set(field, value); remove(field, value?); delete(); }
```

`TxEntity` — not an exported name, just the shape these verbs accept — is a record id (`number`), a `TxHandle`, a lookup by unique key (`[User.sub, "abc"]`), or a temporary id string. `field` is a handle (`Issue.title`) or its full name (`":issue/title"`).

```ts title="examples/reef/src/app/mutations.ts"
export const setDescription = (db: ReefDb, issueId: number, text: string) =>
  db.transact(function* (tx) {
    if (text === "") yield* tx.remove(issueId, Issue.description);
    else yield* tx.set(issueId, Issue.description, text);
  });
```

```ts title="examples/reef/src/app/mutations.ts"
  db.transact(function* (tx) {
    if (on) yield* tx.set(issueId, Issue.labels, labelId);
    else yield* tx.remove(issueId, Issue.labels, labelId);
  });
```

Rules:

- A single-value field: `set` replaces the old value. A many-valued field: one `set` per value; `remove(field, value)` removes one value, `remove(field)` removes them all.
- `delete` removes every fact of the record. History keeps them.
- A reference field takes the target's id (`issue.set(Issue.creator, myEid)`). `put` also accepts a handle, `{ id }` row, `op.principal`, or lookup in a ref slot — not a bare string (that would mint a dangling record).
- There is no `preset` on the client; presets are a [policy](/reference/policy/) feature the server applies.
- **`TxReport`** is `{ t, txEid, datomCount, dbAfter }`. It has no `tempids`; to learn a new record's id, query for it — `report.dbAfter` reads your own write ([glossary](/concepts/glossary/#dbafter)).

### Upserts

Including a `unique: "upsert"` field in the map makes `put` ensure-this-row-exists — the engine unifies with the existing row. `op.put(User, { sub, name })` is insert-or-update; `op.put(User, { sub })` is enough when you only have the key. A lookup that misses is still a hard rejection.

`put(Entity, id, …)` with a nonexistent id mints that id (same as `set`). A two-element array that starts with an ident is a lookup on a ref field; on a many-valued string field, `tags: [":alpha", "beta"]` writes both strings.

```ts
const who = yield* db.principal();
const myEid = who.eid; // the peer-owned user row
```

## Queries

**`Query.from(Entity)`** builds a **query** — a typed description of a read, built as a value ([glossary](/concepts/glossary/#query)); `Query` is the `Query` namespace on `ramose/db` (`Ramose.Query` when you import the module as a namespace). The chain is immutable. `Query.q` remains the generator/kernel constructor for joins, aggregates, and disjunction ([The query language](/reference/query-language/)). Put changing values in `.where` and pass the value to `db.query` / `db.live` / `useLive` — no bindings argument.

```ts
Query.from(Todo)                         // every todo…
  .where({ owner: me })                  // …owned by me
  .select({ id: Todo.id, title: Todo.title })  // the shape; without it the row is the full entity
  .orderBy(Todo.title, "asc", { empty: "last" })
  .limit(20)
  .offset(0);
```

**Combinators** — each is a pipeable stage on the query, and the same name applied to a bound handle is the plain generator fragment:

| combinator | meaning |
| --- | --- |
| `entities(N)` | the source: every record of one type |
| `byId(id)` | the focus is this record — the blessed spelling of a filter by entity id (`id`: number or id cell). Equivalent to `is(N.id, id)` |
| `is(attr, v)` | the field equals `v` — for a reference, points at that record (`v`: literal or id cell). `is(N.id, id)` is the same filter as `byId(id)` |
| `has(attr)` / `missing(attr)` | the fact is there / is not there |
| `matching(attr, (v) => cmp)` | bind the value and constrain it: `matching(Issue.title, (t) => Q.startsWith(t, "Fix"))`; comparisons are `Q.eq` `Q.ne` `Q.lt` `Q.lte` `Q.gt` `Q.gte` `Q.in` `Q.startsWith` `Q.endsWith` `Q.includes` `Q.matches` (a `RegExp` with flags throws) |
| `ids()` | project only `{ id }` rows — the cheap live-subscription workhorse |
| `follow(ref)` / `backlink(ref)` | refocus on the reference's target / on the referrer |
| `some(ref, …ps)` / `every(ref, …ps)` / `none(ref, …ps)` | quantify over referrers through `ref` (`every` / `none` are vacuously true of a record nothing points at) |
| `updatedSince(t)` / `assertedBy(attr, who)` | time and provenance clauses |
| `select(shape)` / `orderBy(key, dir?, opts?)` / `limit(n)` / `offset(n)` | shape, sort, page — on the server |
| `stage(fragment)` | lift your own fragment with the same adapter the shipped combinators use |

`Q.or(…)` / `Q.not(…)` combine clauses (generator spelling); join variables are whatever outer handles the branches close over. `Query.rule(name, body)` names a fragment as an engine rule — that is what makes recursion work — and `q.open(args)` / `Query.enrich` / `Query.refine` compose whole queries; see [The query language](/reference/query-language/).

**Terminals** — methods on the built query value:

```ts
q.one()          // at most one row — Row | null; forces :limit 1
q.oneOrFail()    // exactly one row — Row, or fails with NotOne; forces :limit 2
q.after(cursor)  // keyset page — resolves to { rows, cursor }
q.logic()        // the query without its cursor (orderBy/limit/offset/one/after) — for composition
```

```ts title="examples/reef/src/domain/queries.ts"
export const commentsQuery = (issueId: Ramose.Eid<typeof Issue>) =>
  Query.from(Comment)
    .where({ issue: issueId })
    .select(commentShape)
    .orderBy(Comment.at, "asc");
```

**Shapes.** The **shape** is the fields you ask for ([glossary](/concepts/glossary/#shape)): direct fields, `ref.select({ … })` for nested records, `ref.select(Ramose.all(N))` for the target's wildcard row (ident-keyed), `ref.select(Ramose.again(n))` for the same card again under itself to a hop bound you name (`1`–`16`; last hop is `{ id }`; a many-valued again edge needs `{ limit: n }` in its select options; the shape must select `N.id`), `.optional` for fields that may be absent, `.orDefault(v)` for a missing single-value scalar that should read as `v`. A **reference** reads backwards in a shape with `.reverse` — many-valued, unless the reference is `{ owned: true }` (then the reverse is one record). A many-valued reference filters, orders, and pages its own collection inside the pull with an options record on its `.select` — `ref.select(shape, { where, orderBy, limit, offset })`, where `where` entries are the same filter fragments queries use; a many-valued scalar takes the same record through `Ramose.values(attr, { where, limit, offset })`. `Ramose.all(Todo)` is the wildcard shape — every attribute the matched record has, keyed by name.

```ts title="examples/reef/src/domain/queries.ts#board-shape"
export const boardShape = {
  id: Issue.id,
  title: Issue.title,
  status: Issue.status,
  priority: Issue.priority,
  rank: Issue.rank,
  createdAt: Issue.createdAt,
  creator: Issue.creator.select(personShape),
  assignee: Issue.assignee.select(personShape).optional,
  labels: Issue.labels.select(labelShape),
} as const;
```

**Recursive trees.** A thread is a window, not one fetch. `again(4)` and `{ limit: 20 }` is the first paint; the `{ id }` stub is the next root — same query, `useLive(db, thread(clicked.id))`. Sibling "load more" pages that parent's replies. The JSON: [Read data](/guides/queries/#a-tree-is-a-window).

```ts
const thread = (root: Ramose.Eid<typeof Comment>) =>
  Query.from(Comment)
    .where(Query.byId(root))
    .select({
      id: Comment.id,
      body: Comment.body,
      replies: Comment.replies.select(Ramose.again(4), {
        orderBy: Comment.createdAt,
        limit: 20,
      }),
    });
// Query.is(Comment.id, root) is the same filter as Query.byId(root)
```

**Aggregates.** When the answer is a number, project an aggregate cell in a record — the generator spelling. `Q.count(handle)`, `Q.countDistinct`, `Q.sum`, `Q.avg`, `Q.min`, `Q.max` are cells; the record's other cells are the group keys, and a record of only aggregates is **exactly one row** for the whole match set — over an empty match set each fn answers for the empty set (`count` / `countDistinct` / `sum` are `0`, `avg` / `min` / `max` are `null`), the same rule SQL's ungrouped aggregates follow. A grouped record is `[]` over no rows: no rows, no groups.

```ts
const perStatus = Query.q(function* () {
  const issue = yield* Query.entities(Issue);
  const s = yield* Q.fact(issue, Issue.status);
  return { status: s.v, n: Q.count(issue) };
});
// readonly { status: string; n: number }[] — one row per status
```

Aggregate cells replace the pull shape, so they do not combine with `select` or paging.

**Keyset paging.** `q.after(cursor)` pages a sorted query by position: the result becomes `{ rows, cursor }`, and the cursor — opaque; the last row's sort keys, record id as tie-breaker — is where the next page starts. Pass `null` for the first page; `cursor` is `null` when there is no next page. Unlike `offset`, rows inserted before the cursor never shift the walk. Hold it in memory between pages; it is not designed to be serialized.

```ts
const paged = Query.from(Issue)
  .select(boardShape)
  .orderBy(Issue.createdAt, "desc")
  .limit(20);
const p1 = yield* db.query(paged.after(null));
const p2 = yield* db.query(paged.after(p1.cursor));   // rows strictly after page one
```

Rules the surface enforces:

- Filter stages come before `select` — clauses close before the projection.
- A select field must be a direct field of the queried record type, or a nested `ref.select({ … })`.
- `Ramose.again(n)` is only legal as `ref.select(Ramose.again(n))`. `n` is a literal `1`–`16`. A many-valued again edge needs `{ limit: n }` in its select options. A shape that contains `again` must select `N.id`. The recur edge must land in the same record type as the enclosing shape.
- `orderBy` across a many-valued attribute throws — a sort key is one value per row.
- Everything — filter, order, limit, offset, `one()` / `oneOrFail()`, aggregates, the cursor seek — runs on the server; `limit(20)` really is 20 rows, and `one()` asks for one.
- `after` needs an `orderBy`, and does not combine with `offset` (a cursor already is the offset) or `one()`. A query with a cursor does not delegate into another query — strip it with `q.logic()`.

Not shipped: post-group filters (`having`) on the client surface, ordering or paging groups, full-text search, cross-database joins.

## Pull

**`db.pull(subject, shape)`** reads one record ([glossary](/concepts/glossary/#pull)). The subject is `{ id }` or a **lookup by unique key** `[User.sub, "abc"]` ([glossary](/concepts/glossary/#lookup)); a bare number is a type error. The shape is the same grammar as `.select`, including `.orDefault(v)`, `Ramose.all(N)`, and `ref.select(Ramose.again(n))`.

```ts
db.pull(issueId, { title: Issue.title, description: Issue.description.optional });
db.pull(todoId, { done: Todo.done.orDefault(false) });
db.pull(issueId, Ramose.all(Issue));
db.pull([User.sub, "user_ada"], { name: User.name });
```

Result rules:

- `null` when the record is missing **or a required (non-`.optional`) field is absent** — including a field the policy hides from you.
- An unknown field in the shape is `InvalidRequest`.
- `Ramose.Pull<typeof Todos, typeof shape>` names the result type.

```ts title="examples/reef/src/domain/queries.ts#issue-extra-shape"
export const issueExtraShape = {
  title: Issue.title,
  description: Issue.description.optional,
  // Read-masked for member/viewer (policy.ts): must be `.optional`, so for
  // them the row survives and the field is simply absent.
  privateNote: Issue.privateNote.optional,
} as const;
```

## Errors

Nine tagged request errors, one union: `TxRejected` `Unavailable` `InvalidRequest` `DatabaseNotFound` `Unauthorized` `QueryBudgetExceeded` `InternalError` `NetworkError` `OperationRejected`, and `DbError`. `.oneOrFail()` can also fail with `NotOne` (the query succeeded; the count did not). A policy that does not compile throws `PolicyError`. Match with `try/catch` and `instanceof` / `_tag`; `Ramose.isDatabaseError(e)` is the guard. Each is described on [Errors](/reference/errors/).

```ts
try {
  await db.query(query);
} catch (e) {
  if (e instanceof Ramose.QueryBudgetExceeded) return [];
  throw e;
}
```
