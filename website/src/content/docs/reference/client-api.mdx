`ramose/db` is the portable authoring half of Ramose. It defines schemas,
queries, pulls, authoritative operations, and tagged errors. It does not open a
database connection, send requests, subscribe to changes, or install a schema.

`ramose` re-exports that authoring surface and adds deployment resources, JWT
claim minting, providers, peer constants, and HTTP error mapping.

*New here? Start with [Getting started](/getting-started/quickstart/).*

## Install and import

```sh
bun add ramose effect@rc
```

## Effect is a required peer

Effect is a required peer because operation input and output codecs are Effect
Schemas. Declaring it directly keeps pnpm and Yarn PnP resolution legal and
ensures the application and Ramose use one compatible Effect instance.

```ts
import * as Ramose from "ramose/db";
import * as S from "effect/Schema";
```

## Schema

Build a catalog from entities, traits, fields, and the built-in stored value
types.

```ts title="examples/todos/schema.ts#todo-schema"
import * as Ramose from "ramose/db";

export const Todo = Ramose.Entity("todo", {
  title: Ramose.string(),
  done: Ramose.boolean(),
  createdAt: Ramose.timestamp(),
});

export const Todos = Ramose.Schema({ todo: Todo });
```

The value helpers are `string`, `boolean`, `int`, `float`, `timestamp`,
`uuid`, `bytes`, `Enum`, and `Ref`. `Field` adds cardinality, uniqueness,
and ownership. `Trait` defines reusable field groups. `stored` associates a
custom Effect Schema with its database value type.

```ts
const Label = Ramose.Entity("label", {
  name: Ramose.Field.unique(Ramose.string(), "upsert"),
});

const Issue = Ramose.Entity("issue", {
  title: Ramose.string(),
  labels: Ramose.Field.many(Ramose.Ref(Label)),
  priority: Ramose.Enum(["low", "medium", "high"]),
});
```

## Queries

`Query.from(Entity)` builds an immutable typed query value. `Q` exposes the
lower-level query language for joins, rules, aggregates, and disjunction.
Queries are declarations for a later data-plane adapter; this package version
does not ship an online `Db` runtime that executes them.

```ts
export const openTodos = Ramose.Query.from(Todo)
  .where({ done: false })
  .select({ id: Todo.id, title: Todo.title })
  .orderBy(Todo.createdAt, "desc");
```

## Pull

Pull helpers are `all`, `pick`, `values`, and `again`. They construct typed
selection shapes and recursive pull patterns.

## Db

This release intentionally has no public online `Db` handle. `ramose/db`
authors values for the authoritative peer and future data-plane adapters; it
does not expose `connect`, `query`, `run`, `live`, or `install` methods.

## Authoritative operations

An `Operation` declares a stable wire name, Effect Schema codecs, and an
authoritative body. The body builds transaction data; it is not an optimistic
client prefix and is never executed by `ramose/db` against local state.

```ts
export const addTodo = Ramose.Operation(
  "todo/add",
  {
    input: S.Struct({ title: S.String }),
    output: S.Struct({ id: Ramose.EntityId }),
  },
  (op, input) => ({
    id: op.put(Todo, {
      title: input.title,
      done: false,
      createdAt: new Date(),
    }),
  }),
);
```

Use `Operation.patch` for standard field updates. `Operations` and
`defineOperations` create registries shared with the peer. `operationNames`,
`operationCards`, and `checkOperationsCoverage` inspect or validate a registry.

## Writes

Writes are declared inside authoritative operation bodies with `put`, `update`,
`set`, `remove`, and `delete`. `ramose/db` does not execute those operations or
expose a raw transaction submission API.

## Names and errors

`DATABASE_NAME_RE` and `isDatabaseName` validate database names.
`IDENT_NAME_RE`, `isIdentName`, `RESERVED_FIELD_KEYS`, and
`isReservedFieldKey` validate entity and field names.

Request failures use the tagged `DbError` union: `InvalidRequest`,
`Unauthorized`, `DatabaseNotFound`, `QueryBudgetExceeded`, `TxRejected`,
`OperationRejected`, `Unavailable`, `InternalError`, and `NotOne`.
`isDatabaseError` narrows unknown values.

## Deploy-time additions

Import `ramose` in Alchemy stack files. It adds `Server`, `Database`,
`providers`, `Providers`, `claims`, `Claims`, `AuthConfig`, peer compatibility
constants, and `errorToHttp` / `errorResponse`.

```ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as Ramose from "ramose";

const server = Ramose.Server("Ramose", {
  databases: { todos: Todos },
});

export default Alchemy.Stack(
  "app",
  {
    providers: Layer.mergeAll(Cloudflare.providers(), Ramose.providers()),
    state: Cloudflare.state(),
  },
  Effect.gen(function* () {
    yield* server;
  }),
);
```

`ramose/worker` is the peer Worker entry. Use
`import.meta.resolve("ramose/worker")` when a Cloudflare resource expects a
filesystem path. `ramose/better-auth` is the optional Better Auth integration.
