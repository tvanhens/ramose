`ramose/client` owns authorized browser replicas, graph handles, local query execution, synchronization, the durable outbox, optimistic layers, and receipts.

*New here? Start with [Build your first Ramose web app](/getting-started/quickstart/).*

## createClient

```ts
import { createClient } from "ramose/client"

const client = createClient({
  url: "https://data.example.com",
  token: () => session.accessToken,
  catalog: AppCatalog,
})
```

The client is framework-neutral. One instance coordinates all tabs for the same origin and principal. Close it when the signed-in principal changes permanently.

## Open the authorized root

```ts
const rootDb = client.open()
```

The token and server determine the root. Callers cannot choose an internal database or catalog id.

## Traverse to a child graph

```ts
const projectDb = rootDb.query
  .from(Project)
  .where(Project.slug.eq("launch"))
  .one()
  .db()
```

`.db()` is available only from an entity that implements a graph trait. Equivalent handles are interned. Creating a handle is cheap and does not activate synchronization; observing a query does.

## Observe a query

```ts
const unsubscribe = projectDb.observe(
  projectDb.query.from(Task).orderBy(Task.createdAt, "desc"),
  (state) => { /* render or update a store */ },
)
```

Query state is a tagged union:

```ts
type QueryState<A> =
  | { status: "pending" }
  | { status: "ready"; data: A }
  | { status: "stale"; data: A }
  | { status: "error"; error: unknown }
```

`stale` retains a complete local result while catch-up is pending or the network is unavailable. Disposing the last observer stops maintaining that query. The activated graph replica remains available for the session and future offline use.

## Entity handles

Querying entities returns handles with separate application data and local state:

```ts
task.data.title
task.local.pending
task.local.receipts
task.mutate.setDone({ done: true })
```

`.data` is plain cloneable data. `.local` contains client-only pending and reconciliation metadata. `.mutate` contains operations owned by the entity and its traits.

## Targetless operations

```ts
const receipt = projectDb.mutate.createTask({ title: "Ship docs" })
```

Targetless operations live on `db.mutate`. Invocation returns immediately with a durable receipt handle. The optimistic projection, when declared, updates local queries before the server acknowledgement.

## Receipt state

```ts
type ReceiptState<Output> =
  | { status: "queued" }
  | { status: "committed"; output: Output }
  | { status: "rejected"; error: OperationError }
```

The invocation id is assigned before the outbox write and survives reload, reconnect, and tab leadership changes. Observe a receipt when the exact outcome matters; use entity `.local.pending` for lightweight feedback.

## Synchronization state

`client.observeSync(listener)` reports offline, connecting, catching-up, and live transitions independently of query state. A ready query can remain useful offline; a live connection does not imply every receipt committed.

## Persistence and multi-tab behavior

Each activated graph has a persistent IndexedDB replica. Tabs share durable data and elect one network leader per principal and graph. Followers execute local queries and submit intents through the shared outbox. Closing one tab does not discard queued work.
