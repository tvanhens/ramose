The TypeScript query builder creates immutable, serializable query values. The browser runs them against a local replica; the server runs the same representation against its authorized database view.

*New here? Start with [Read data](/guides/queries/).*

## Start from an entity or trait

```ts
db.query.from(Task)
db.query.from(Assignable)
```

An entity source returns that exact type. A trait source returns every visible entity that implements the trait. One query belongs to one `db` handle and cannot cross into a child graph.

## Predicates

```ts
query
  .where(Task.done.eq(false))
  .where(Task.priority.in(["high", "urgent"]))
  .where(Task.createdAt.gte(since))
```

Typed field expressions expose compatible equality, comparison, membership, text, presence, and reference operators. Combine predicates with `and`, `or`, and `not`. Literal input is validated before execution.

A reference is compared by entity identity — the `EntityId` a query published, or the `ClientRef` of an entity this device created. Both are branded with the entity they name, so an identity of another type is a compile error; one this replica holds nothing for matches nothing rather than failing, and an identity anywhere an entity cannot be held is refused when the query is built.

## Relationships

Traverse declared references and relationships from a bound source. Relationship clauses participate in the query; nested projection controls returned shape.

```ts
db.query
  .from(Task)
  .where(Task.assignee.email.eq(viewer.email))
  .select({
    id: Task.id,
    title: Task.title,
    assignee: { name: Task.assignee.name },
  })
```

Traversal never bypasses policy. Hidden facts are absent from the database capability the query sees.

## Projection

Without an explicit projection, entity queries return entity handles. `.select({...})` returns the declared plain-data shape. Select only fields needed by the caller, especially for MCP and nested results.

## Ordering and pages

```ts
query
  .orderBy(Task.updatedAt, "desc")
  .orderBy(Task.id, "asc")
  .page({ first: 50, after: cursor })
```

Use a stable tie-breaker for deterministic pages. Cursors are opaque and scoped to the query, graph, authorization view, and basis that produced them.

## Cardinality

```ts
query.all()       // zero or more
query.first()     // zero or one
query.one()       // exactly one
```

`.one()` fails when the authorized query does not produce exactly one result. Do not use the distinction between zero and hidden as an authorization signal.

## Rules and recursion

Named rules package reusable relational logic. Recursive rules require an explicit depth or result bound. Keep rule inputs and outputs typed, and compose rules from the same query clauses as ordinary reads.

## Lowering and portability

Every supported builder query lowers to `QueryDocumentV1`. Unsupported closures, functions, classes, and runtime objects are rejected before transport. Use the document form directly for language-neutral clients and MCP.

## Cost controls

The runtime budgets candidate work, projection width, relationship expansion, recursion, page size, and execution time. `query_budget_exceeded` is not retried automatically; narrow the request.
